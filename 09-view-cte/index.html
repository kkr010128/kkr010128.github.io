MariaDB Inline View, View, 임시 테이블, CTE 정리

Dohyeon Kim 2026년 7월 15일 · 4분 읽기

1. 인라인 뷰 (Inline VIEW)

  • SELECT 구문의 결과는 테이블의 구조를 가짐
  • FROM에는 테이블의 이름을 기술하는데 이 절에 SELECT 구문을 작성해서 테이블처럼 사용하는 것이 가능
  • 이 테이블은 SQL문이 수행되는 동안만 존재하는 임시적인 테이블이라서 LINE VIEW라고

  • 다른 절에서 이 테이블을 이용하고자 하면이름을 만들어줘야 함

  • 정의: FROM 절에 사용하는 서브쿼리를 의미함. 서브쿼리가 반환하는 결과 셋을 하나의 임시 테이블처럼 취급함.
  • 특징: 영구적으로 저장되지 않고 쿼리 실행 시에만 일시적으로 생성됨. 반드시 별칭(Alias)을 지정해야 필드 참조가 가능함.
  • 예제: 과장/부장급 중 성취도 70점 이상인 직원 조회
-- tStaff 테이블에서 grade가 과장 또는 부장이고, score는 70인 데이터를 조회
SELECT *
FROM (SELECT * FROM tStaff WHERE grade = '과장' OR grade = '부장') A
WHERE A.score >= 70;

2. 뷰 (VIEW) 개요

  • 정의: 하나 이상의 테이블로부터 유도된 논리적 가상 테이블임. 실제 데이터를 물리적으로 저장하지 않고 정의(SQL구문, SELECT 문장)만 메모리에 저장함.
  • 사용 이유:
    • 복잡성 단순화: 길고 복잡한 조인 쿼리를 매번 작성하지 않고 뷰를 통해 간단히 조회 가능함.
    • 보안성: 원본 테이블의 특정 컬럼만 공개하여 데이터 접근 권한을 제한할 수 있음.
      • 테이블에서 사용하는 데이터가 사용자 별로 다른 경우 필요한 데이터만 제공할 수 있음.
    • 독립성: 원본 테이블 구조가 바뀌어도 뷰 정의만 수정하면 응용 프로그램은 영향을 받지 않음.

3. 뷰 생성 및 관리

3.1 뷰 생성 문법

CREATE [OR REPLACE] VIEW 뷰_이름
[(별칭1, 별칭2, ...)]
AS SELECT 문장
[WITH CHECK OPTION]
[WITH READ ONLY];

3.2 주요 옵션

  • OR REPLACE: 동일 이름의 뷰가 있으면 삭제하지 않고 덮어씀.
  • WITH CHECK OPTION: 뷰의 조건 범위 내에서만 INSERT, UPDATE가 가능하도록 제한함.
  • WITH READ ONLY: 뷰를 통한 데이터 변경(DML)을 원천 차단하고 조회만 가능하게 함.

3.3 실무 예제 및 결과

  • 뷰 생성 (30번 부서 전용):
CREATE VIEW EMP_VIEW30 AS
SELECT EMPNO, ENAME, DEPTNO FROM EMP_COPY WHERE DEPTNO = 30;

-- 조회 결과
SELECT * FROM EMP_VIEW30; -- 30번 부서원들의 사번, 이름만 출력됨.
  • 복합 뷰 생성 (사원+부서 조인):
CREATE VIEW EMP_VIEW_DEPT AS
SELECT E.EMPNO, E.ENAME, D.DNAME, D.LOC
FROM EMP E, DEPT D
WHERE E.DEPTNO = D.DEPTNO;

4. 뷰의 분류 및 DML 제약 사항

| 구분 | 단순 뷰 (Simple VIEW) | 복합 뷰 (Complex VIEW) | | :———– | :——————————— | :—————————- | | 대상 테이블 수 | 1개 | 2개 이상 (JOIN) | | DML 작업 | 가능함 (제약 조건 준수 시)
DISTINCT 사용 불가 | 제한적이거나 불가능함
DISTINCT 사용 가능 | | 함수/그룹화 | 포함하지 않음 | 포함 가능함 |

  • 뷰에 DML 작업을 하게 되며 원본 테이블의 데이터가 수정됨

    4.1 DML이 불가능한 경우

  • 뷰 정의에 포함되지 않은 컬럼이 원본 테이블에서 NOT NULL인 경우 (INSERT 불가).
  • 산술 표현식(예: SAL * 12)으로 정의된 컬럼을 수정하려는 경우.
  • DISTINCT, GROUP BY, HAVING, 집계 함수가 포함된 뷰인 경우.

5. 임시 테이블 (TEMPORARY TABLE)

  • 정의: 세션(Session) 내에서만 생존하는 테이블임. 접속을 끊으면 자동으로 삭제됨.
  • 특징: 생성한 클라이언트 본인만 볼 수 있으며, 기존 테이블과 이름이 같으면 임시 테이블이 우선권을 가짐.
    • 임시 테이블은 메모리에 생성됨
  • 문법:
CREATE TEMPORARY TABLE IF NOT EXISTS temp_table (
    id INT, name VARCHAR(10)
);

6. CTE (Common Table Expression)

  • 정의: 복잡한 쿼리 내에서 임시 결과 셋을 정의하여 반복 사용하는 구문임. (WITH 절 사용)
    • DB에 실제 저장되는 객체 이므로 사용 후 정리해야 한다는 면에서 번거로움
    • 객체를 생성하고 저장 공간을 차지하기 때문에 속도도 그다지 빠르지 않음
  • 장점: 임시 테이블보다 생성/정리 비용이 적고 가독성이 우수하며 성능상 이점이 있음.
    • 기존 테이블의 컬럼 이름을 변경해서 가독성을 높이기도 함
    • 여러개 생성도 가능함
    • 대부분의 경우는 VIEW로 동일한 문제를 해결
  • 예제: 쇼핑 정보를 CTE로 정의 후 평균 구매수량 이상인 데이터 조회
-- WITH 테이블이름(컬럼이름 나열) AS (쿼리문)
1. tSTaff 테이블에 DEPART가 영업부이고 GENDER가 남인 데이터에서 SALARY가 평균 이상인 데이터의 NAM, SALARY, SCORE를 조회
   
WITH TEMP AS(SELECT NAME, SALARY, SCORE FROM tStaff WHERE DEPART='영업부' AND GENDER '남')
SELECT * FROM TEMP WHERE SALARY >= (SELECT AVG(SALARY) FROM TEMP);

WITH SHOPPING AS (
    SELECT M.MEMBER, O.ITEM, O.NUM
    FROM tMember M INNER JOIN tOrder O ON M.MEMBER = O.MEMBER
)
SELECT * FROM SHOPPING
WHERE NUM >= (SELECT AVG(NUM) FROM SHOPPING);

[!tip] Obsidian 정리 팁

  • 뷰는 실제 데이터를 가진 것이 아니므로 DROP VIEW를 수행해도 원본 데이터는 삭제되지 않음을 명시함.
  • 실무에서는 데이터 정제 단계에서 CTE를 적극 활용하여 쿼리의 가독성을 확보하는 것이 좋음.

Maria DB에서는 읽기 전용을 만들고자 하는 경우 사용자에게 뷰를 조회할 수 있는 권한 부여해서 읽기 전용을 만들어줌 뷰에 대한 권한을 전부 준 후 삽입, 삭제, 수정 권한을 회수하는 방식으로 설정

GRANT SELECT ON 데이터베이스이름.뷰이름 TO '사용자계정'@'접속위치';

REVOKE INSERT, UPDATE, DELETE
ON 데이터베이스이름.뷰이름 TO '사용자계정'@'접속위치';

VIEW와 CTE의 차이

  • VIEW는 한 번 만들어지면 삭제할 때까지 데이터베이스에 남아있음
  • CTE는 한 번 사용하고 나면 자동으로 삭제됨
  • VIEW는 SQL 구문을 메모리에 저장하지만 CTE는 데이터를 메모리에 저장함
    • 따라서 CTE의 조회 속도가 더 빠름
