- 파드 정보 확인: kubectl get pods sample-env -o yaml

=>컨테이너 정보
- 컨테이너 정보는 resourceFieldRef를 사용하여 확인 가능
- 컨테이너 정보를 환경 변수에 저장하는 매니페스트(sample-env-container.yaml)
apiVersion: v1
kind: Pod
metadata:
  name: sample-env-container
  labels:
    app: sample-app
spec:
  containers:
  - name: nginx-container
    image: nginx:1.17
    env:
    - name: CPU_REQUESTS
      valueFrom:
        resourceFieldRef:
          containerName: nginx-container
          resource: requests.cpu
    - name: CPU_LIMITS
      valueFrom:
        resourceFieldRef:
          containerName: nginx-container
          resource: limits.cpu

=>환경 변수를 사용할 때 주의할 점
- 쿠버네티스에서 command 나 args로 실행할 명령어를 지정하는데 매니페스트에 작성된 환경 변수를 사용할 때 ${환경변수} 로 하면 안되고 $(환경변수)로 해야 합니다.
- 명령어에 잘못 지정한 환경 변수(sample-env-fail.yaml)
apiVersion: v1
kind: Pod
metadata:
  name: sample-env-fail
  labels:
    app: sample-app
spec:
  containers:

    - name: TESTENV
      value: "100"

- command 나 args는 매니페스트 내에서 만든 환경변수에만 접근이 가능
운영체제에서 접근 가능한 환경 변수는 별도의 스크립트 파일을 만들어서 처리를 해야 합니다.

2)Secret
=>기밀 정보를 전달하는 방법
- 도커 빌드 시 컨테이너 이미지에 추가
이미지를 빌드할 때 애플리케이션 측이나 컨테이너 환경 변수 및 실행 인수 등에 패스워드 등을 추가할 수 있지만 이미지 자체에 기밀 정보가 포함되어 있으면 도커 레지스트리에 기밀 정보도 업로드하게 되어 보안상 바람직하지 않음

기밀정보 내용을 변경하려면 이미지를 다시 빌드해야 함

- 파드나 디플로이먼트의 매니페스트를 통해 전달
깃 저장소와 같은 외부 서버에서 기밀 정보를 포함한 매니페스트를 관리하면 보안상 위험
여러 애플리케이션에서 같은 기밀 정보를 사용할 경우 매니페스트 관리가 어려움

- 사용자 이름이나 패스워드 등의 기밀 정보를 별도의 리소스에 정의하고 파드에서 읽어 들이는 시크릿 리소스 사용

- 시크릿을 정의하고 있는 매니페스트는 base64로 인코드되어 있지만 암호화되어 있지 않아서 매니페스트 파일을 깃 저장소에 업로드하는 것은 불가능한데 이러한 문제를 해결하기 위해서 시크릿이 정의된 매니페스트를 암호화하는 kubesec/SealedSecret/ExternalSecret 같은 소픈 소스 소프트웨어를 사용

=>시크릿 분류
- 타입 목록
Opaque: 일반적인 범용 용도
kubernetes.io/tls: TLS 인증서용

kubernetes.io/dockerconfigjson: 도커 레지스트리 인증 정보용

bootstrap.kubernetes.io/token: 부트스트랩 토큰용

=>일반적인 범용 용도의 시크릿
- 생성 방법
파일에서 값을 참조하여 생성: --from-file
envfile에서 값을 참조하여 생성: --from-env-file
직접 값을 전달하여 생성: --from-literal
매니페스트에서 생성: -f

- 파일로부터 생성
파일에 확장자를 붙이지 않는 것을 권장
파일명이 키가 되므로 파일명에 확장자를 잘 붙이지 않음

시크릿에 포함된 값을 내보내기
echo -n "root" > ./username
echo -n "rootpasswor" > ./password

파일을 가지고 시크릿을 생성
kubectl create secret generic --save-config sample-db-auth --from-file=./username --from-file=./password

data를 확인: base64로 인코딩 되서 조회
kubectl get secrets sample-db-auth -o json | jq .data

원문을 확인
kubectl get secrets sample-db-auth -o jsonpath='{.data.username}' | base64 -d

- 여러 개의 secret을 하나의 파일로부터 읽고자 하는 경우에는 envfile을 이용
파일을 생성(env-secret.txt)
username=root
password=rootpassword

시크릿 생성
kubectl create secret generic --save-config sample-db-auth --from-env-file=./env-secret.txt

원문을 확인
kubectl get secrets sample-db-auth -o jsonpath='{.data.username}' | base64 -d

- 직접 입력해서 시크릿을 생성
kubectl create secret generic --save-config sample-db-auth --from-literal=username=root

- Base64로 인코딩 된 값을 매니페스트에 추가(sample-db-auth.yaml)
apiVersion: v1
kind: Secret

  name: sample-db-auth

- 생성할 때 data대신에 stringData를 사용하면 Base64 인코딩이 필요없음

3)ConfigMap
=>개요
- 설정 정보 등을 Key-Value 로 저장할 수 있는 데이터 저장 리소스
- 설정 파일 자체를 저장할 수 있음
- 하나의 ConfigMap에 저장할 수 있는 최대 용량은 1MB
- 설정 파일 자체를 ConfigMap에 저장해도 되고 특정 파라미터만 저장하는 것도 가능

=>ConfigMap 생성
- kubectl create 명령으로 생성하는데 --from-file 옵션으로 파일로부터 생성 가능하고 직접 입력한 문자열을 이용할 때는 --from-literal 옵션 지정이 가능
- 파일로부터 만들면 파일 이름이 key가 됩니다.
- nginx.conf 파일을 ConfigMap으로 생성
nginx.conf 파일을 생성

user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid

ConfigMap 생성: kubectl create configmap --save-config sample-configmap --from-file=./nginx.conf

데이터 확인: 
kubectl get configmaps sample-configmap -o json | jq .data

kubectl describe configmaps sample-configmap
