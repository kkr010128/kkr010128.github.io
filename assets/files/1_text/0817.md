=>명령어
- 저장: docker image save [옵션] 이미지이름 > 파일경로
- 로드: docker image load < 파일경로

=>이미지 저장 및 로드
- eclipse/mysql 다운로드: docker pull eclipse/mysql

- 이미지 확인
docker images
docker image ls -aq

- 이미지를 로컬에 파일로 압축해서 저장
docker image save eclipse/mysql < test_mysql.tar

- 파일 확인
ls

- 파일로부터 불러오기
docker image load < test_mysql.tar

- 이미지 확인
docker images
docker image ls -aq

=>이미지 삭제
docker image rm [옵션] {이미지 이름[:태그]} | imageID}
docker image rm 대신에 docker rmi 명령도 가능

- 옵션
f(force): 강제 삭제

a(all): 모든 이미지 관련작업에서 사용

--no-prune: 삭제 후 dangling parent image를 자동삭제하지 않음

- 스크립트 변수 사용 가능
$(명령어)

전체 이미지를 삭제: 	docker rmi $(docker images -q)
				docker rmi -f $(docker images -q)

- 사용중이 아닌 이미지 제거
docker image prune -a

4.Container
1)개요
=>이미지는 읽기 전용의 불변 값으로 만들어지는데 이런 이미지를 바탕으로 Docker 엔진은 컨테이너를 생성할 수 있는데 이 때 이미지 와 함께 읽고 쓰기 가능한 레ㅇ어를 추가해서 만들어지는 것이 컨테이너
=>도커 이미지는 컨테이너 동작과 관련된 컨텐츠를 제공하고 이를 바탕으로 컨테이너의 동작이 이루어지기 때문에 컨테이너 명령 대부분이 서비스 실행 및 운영과 관련되어 있음
=>Docker 컨테이너는 Docker 이미지의 Snapshot
=>컴퓨터 내에서 동작하는 애플리케이션은 프로세스로 실행이 되는데 컨테이너는 격리된 공간에서 실행되는 프로세스
=>컨테이너는 프로세스 격리 기술의 표준으로 정의된 OCI(Open Container Initative)로 컨테이너 포맷과 런타임에 대한 개방형 업계 표준을 만들기 위한 목적으로 리눅스 파운데이션의 지원을 받아서 구성된 프로젝트

=>컨테이너 삭제: docker rm container-test1

3)컨테이너 생성 주기
=>실행
- docker run 이나 start 명령의 인자로 지정된 docker image를 기반으로 container가 생성되면 image를 생성했던 Dockerfile에 포함된 CMD 및 ENTRYPOINT 명령에 정의된 애플리케이션 실행되고 이 애플리케이션들이 실행 중인 상태가 실행 상태
- 일반 프로세스와 마찬가지로 데몬 형태로 계속 실행하는 컨테이너도 있고 포그라운드 프로세스처럼 한 번 작업하고 중지 상태가 되는 컨테이너도 있음

=>중지
- 실행 중인 Container를 사용자가 명시적으로 중지시키거나 애플리케이션이 정상 종료 또는 오류로 인한 종료를 막론하고 정지 상태가 됩니다.
- 중지 상태가 되면 이전 시점의 상태가 그대로 저장되서 재시작이 가능

=>파기
- 중지 상태인 컨테이너는 명식적으로 파기하지 않는 이상 디스크에 그대로 남아있음
- 불필요한 컨테이너는 삭제하는 것을 권장
- 파기한 컨테이너는 재시작 할 수 없음

4)애플리케이션 실행
=>docker run
- docker image pull, docker container create, docker container start 명령을 하나로 합친 명령으로 image가 없으면 다운로드도 수행

- 기본 형식
docker run [옵션] 이미지이름 [인자]

- 사용할 수 인자는 이미지에 따라 달라짐

- 옵션
name 컨테이너이름: 컨테이너 이름을 설정하는 것으로 설정하지 않으면 임의로 부여

p [Host Port]:[Container Port]: 포트포워딩
내부 컨테이너 포트에 외부에서 접근하기 위해서 설정
외부에서 접근해야 하는 서비스는 반드시 설정

P(publish-all)=[true|false]
컨테이너 내부에서 사용하는 모든 포트를 임의로 할당해서 포트포워딩

v(volume)=호스트경로:컨테이너경로
컨테이너의 경로를 호스트에 바인딩, 볼륨 마운트

--net=네트워크이름
네트워크 연결, 다른 컨테이너와 라우터를 이용하지 않고 통신하기 위해서 사용

i(interface): 대화식 모드 연결

t: 단말 디바이스 할당(터미널 할당), 외부에서 컨테이너 내부에 직접 접속하고자 하는 경우 선택

d(detach)
백그라운드에서 실행
이 옵션이 있어야 데몬으로 동작
it 옵션과 같이 사용하는 경우가 많음

e(env)
환경변수 지정

rm: 컨테이너 종료할 때 자동으로 컨테이너 파기

restart = [no | on-failure | on-failure:횟수 | always]: 컨테이너 종료 시 재시작 정책

h 컨테이너의호스트이름: 컨테이너의 호스트 이름을 지정하는 옵션인데 미지정시 컨테이너 ID가 호스트이름으로 설정

link=다른컨테이너ID: 설정하면 컨테이너 이름으로 통신이 가능

=>한 번 만 실행되는 컨테이너 와 데몬 형태로 동작하는 컨테이너
- d는 컨테이너를 백그라운드로 실행하는 옵션이고 i 와 t는 컨테이너 내부에 터미널로 접속하기 위해 사용하는 옵션
- d를 사용하지 않으면 컨테이너는 포그라운드 형태로 실행이 되기 때문에 컨테이너 사용이 끝날 때 까지 다음 명령을 입력할 수 없는 상태가 됨 
- i 와 t를 설정하지 않으면 컨테이너 내부로 직접 접속할 수 없기 때문에 파일 시스템에 접근이 불가능

=>실행 중인 컨테이너 확인: docker ps
- 항목 
CONTAINER ID: 컨테이너를 실행하면 부여되는 문자열로 원래는 64글자 이지만 12글자만 출력

IMAGE: 사용한 이미지

COMMAND: 컨테이너를 실행할 때 수행하는 명령어

CREATED: 컨테이너 생성 후 경과 기간

STATUS: 컨테이너의 현재 상태로 실행 중이면 UP

PORTS: 포트포워딩 결과를 출력하는데 호스트포트번호->컨테이너포트번호 순이지만 2개의 포트 번호가 동일한 경우는 뒤의 번호는 출력되지 않음

NAMES: 컨테이너 이름

- 옵션
a: 중지된 컨테이너까지 전부 조회

q: 컨테이너 ID만 표시

aq: 모든 컨테이너의 ID만 표시

l: 가장 최근에 만들어진 컨테이너

n 숫자: 숫자만큼 최근에 만들어지 컨테이너

s: 컨테이너 크기 표시

no-trunc: 컨테이너 ID를 자르지 않고 표시

filter: 조건 검색
	docker ps --filter status=running

format: 포맷 설정
	docker ps --format "{{.ID}} {{.Names}}"

=>파이썬 프로그램을 실행
- 파이썬 코드를 작성(lotto.py)
from random import shuffle
from time import sleep
gamenum = input('count:')
for i in range(int(gamenum)):
  balls = [x + 1 for x in range(45)]
  ret = []
  for j in range(6):
    shuffle(balls)
    number = balls.pop()
    ret.append(number)
  ret.sort()
  print('lotto number[%d]:' %(i+1), end='')
  print(ret)
  sleep(1)

- 실행: python3 lotto.py

5.도커 볼륨
1)볼륨 마운트
=>볼륨: 스토리지의 한 영역을 분할한 것
=>도커 볼륨은 컨테이너에서 생성해서 재사용할 수 있고 호스트 운영체제에서 직접 접근이 가능
=>보전되어야 하는 데이터를 유지하기 위한 매커니즘을 제공
=>컨테이너 내부의 데이터는 컨테이너의 라이프사이클과 연관되어 컨테이너 종료 될 때 같이 삭제가 되므로 별도의 매커니즘을 이용해서 데이터의 영속성을 유지해야 함

2)마운트 방식
=>볼륨 마운트: Docker Engine이 관리하는 영역 내에 만들어진 볼륨
- 볼륨을 생성하고 마운트
- 도커 컨테이너를 이용해서 사용
- 백업 절차가 복잡

=>바인드 마운트: 호스트 컴퓨터의 디렉토리와 연결하는 방식
- 기존 파일이나 디렉토리를 마운트
- 일반적인 파일과 동일한 방식으로 사용
- 일반적인 파일과 동일한 방식으로 백업

4)바인드 마운트 
=>특징
- Volume 마운트보다 사용이 제한적
- 호스트 컴퓨터의 내부 경로를 직접 마운트해서 사용
- 사용자가 파일 또는 디렉토리를 생성하면 해당 호스트 파일 시스템의 소유자 권한으로 연결이되고 존재하지 않는 경우 자동 생성
- 자동 생성된 디렉토리는 루트 사용자 소유
- 컨테이너 실행 시 지정하여 사용하고 컨테이너 제거 시 바인드 마운트는 해제되지만 호스트 디렉토리는 유지

=>명령
docker run -d -v 스토리지실제경로:컨테이너마운트경로 ubuntu

=>실습
- 마운트할 디렉토리를 생성: apache

- httpd 컨테이너를 생성하고 /usr/local/apache2/htdocs 디렉토리와 위에서 생성한 디렉토리를 연결
docker run --name apache -d -p 8000:80 -v /home/adam/apache:/usr/local/apache2/htdocs httpd

- 로컬 디렉토리에 index.html 파일을 만들어서 브라우저나 curl 명령으로 확인
