8)Dockerfile을 사용하는 이유
=>운영체제 이미지를 이용한 PHP 컨테이너 연동: 대부분 베이스 이미지를 제작할 때 사용
- ubuntu:14.04 이미지를 가지고 컨테이너를 생성하는데 바로 접속
docker run --name myweb -p 8000:80 -it ubuntu:14.04

- apache2 설치 및 확인
도커의 운영체제 이미지는 최소의 것만 가지고 만들어지기 때문에 패키지 정보 업데이트를 가장 먼저 수행
apt update
apt install -y apache2
service apache2 start

- 다른 터미널에서 접속해서 확인
curl localhost:8000

- 리눅스 컨테이너 안에서 작업을 수행
기존 웰컴 파일의 이름을 수정
mv /var/www/html/index.html /var/www/html/index.html.org

새로운 웰컴 파일을 생성하고 작성: vim /var/www/html/index.html 

<h1>Hello Docker Application </h1>

- PHP를 설치하고 기본 페이지를 작성해서 확인
apt install -y php5

기본 페이지 작성: vim /var/www/html/index.php
<?php
  phpinfo();
?>

- 확인
curl localhost:8000/index.php

- 현재 컨테이너를 이미지로 변경: 다른 터미널에서 수행
docker commit myweb myphpapp:1.0

- 만들어진 이미지를 가지고 컨테이너를 생성해서 실행
docker run -dit -p 8000:80 --name=myphpapp myphpapp:1.0

=>Dockerfile을 이용해서 위와 동일한 작업을 수행
- 디렉토리를 생성하고 그 디렉토리로 이동

- Dockerfile 생성
#베이스 이미지 설정
FROM ubuntu:20.04

#작성자 정보 - 생략 가능
MAINTAINER "adam <itstudy@kakao.com>"

#이미지에 대한 설명 - 생략 가능
LABEL title "IaC PHP Web Application"

#필요한 패키지 설치
RUN apt update
RUN apt install -y tzdata
RUN apt install -y php
RUN apt install -y apache2
RUN apt install -y git
RUN apt install -y curl
RUN apt install -y ssh
RUN apt install -y wget

#apache 환경변수 설정
ENV APACHE2_RUN_USER www-data
ENV APACHE2_RUN_GROUP www-data
ENV APACHE2_LOG_DIR /var/log/apache2
ENV APACHE2_WEB_DIR /var/www/html
ENV APACHE2_PID_FILE /var/run/apache2/apache2.pid

#기본 웹페이지를 작성
RUN echo "Hello Docker Application." > /var/www/html/index.html

#php 페이지를 작성
RUN echo "<?php phpinfo(); ?>" > /var/www/html/index.php

#포트 노출
EXPOSE 80

#작업 디렉토리 설정 - RUN, CMD, ENTRYPOINT 명령이 실행되는 디렉토리
WORKDIR /var/www/html

#이미지가 컨테이너로 실행 될 때 수행할 명령 - 아파치 서비스를 자동으로 실행
CMD ["/usr/sbin/apache2ctl", "-D", "FOREGROUND"]

- Dockerfile을 이용해서 이미지 생성
docker build -t myphpapp:latest .

- 컨테이너로 실행
docker run -dit -p 8000:80 --name myphpapp myphpapp:latest

9)이미지 빌드 과정
=>Dockerfile 작성 Lifecycle
- Dockerfile은 인프라 구성을 위해 필요한 명령을 저장한 텍스트 파일
- docker build 명령을 통해서 작성한 명령을 순서대로 읽으면 자동으로 이미지를 빌드(생성)
- 빌드는 사용자와의 대화식 처리가 아닌 자동화된 빌드

=>패키지 설치 에러
- Dockerfile 작성
FROM ubuntu:20.04

RUN apt install python

- 이미지 빌드
docker build -t myapp .

- 패키지 설치 시 자동화시키지 않아서 에러가 발생한 것이므로 수정
FROM ubuntu:20.04

RUN apt update
RUN apt install -y python

=>Dockerfile은 새로운 빈 디렉토리에서 생성하여 빌드하는 것을 권장

=>이미지 빌드가 시작되면 현재 디렉토리의 모든 파일과 디렉토리의 내용은 Docker 데몬에 빌드 컨텍스트로 전달되는데 이 때 현재 디렉토리에 있는 파일과 디렉토리 중 제외 대상이 있으면 .dockerignore 파일에 기재하면 됩니다.

=>Dockerfile이 현재 디렉토리나 파일 이름이 다른 경우는 -f 옵션을 이용해서 경로를 지정해 주어야 합니다.

=>docker build는 빌드 속도 향상을 위해서 실행 중간에 있는 이미지 캐시를 이용
- 첫번째 빌드 과정에서 단계 별로 캐시를 생성하고 이 빌드 캐시는 동일한 이미지 작업으로 제한
- 캐시를 적용할 때 순서도 중요합니다.
- 빌드 과정에서 캐시를 사용하지 않으려면 --no-cache를 지정해서 빌드
- 다른 이미지로부터 만들어진 캐시를 사용해 빌드하려면 --cache-from 옵션을 통해 수행
- 비밀번호 등의 민감한 데이터가 포함되는 경우 secret 구축이 가능

#베이스 이미지
FROM python

#패키지 저장소 업데이트하고 불필요한 캐시 삭제

    && apt install -y --no-install-recommends \

COPY . .

#포트 개방
EXPOSE 8000

#컨테이너로 만들어질 때 수행하는 명령: 장고 프레임워크 실행 명령
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]

- 이미지 빌드

- 컨테이너 생성
docker run --name dockerdjango -p 8000:8000 -d dockerdjango:latest

=>go를 이용한 웹 프로그램 작성 및 실행
- 디렉토리 생성 후 이동

- 프로젝트 초기화
go mod init my-go-app

- main.go 작성
package main

import(
        "encoding/json"
        "fmt"
        "net/http"
)
func main(){
        //기본 경로 핸들러
        http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request){
                w.Header().Set("Content-Type", "application/json")
                json.NewEncoder(w).Encode(map[string]string{"message":"Hello From Go"})
        })

        http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request){
                fmt.Fprintf(w, "OK")
        })

        fmt.Println("서버가 8000번 포트에서 시작되어서 대기 중 !!!")

        if err := http.ListenAndServe(":8000", nil); err != nil {
                panic(err)
        }
}

- 실행
go run main.go

=>이미지 생성 및 컨테이너 생성 및 실행

- 이미지 빌드

- 컨테이너 생성
