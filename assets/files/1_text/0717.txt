**Redis
2.Redis 사용
1)설치
=>public cloud 와 같은 곳의 SaaS(서비스-애플리케이션 서비스)를 이용
=>운영체제에 직접 설치
=>Docker 나 Kubernetes 와 같은 컨테이너를 이용해서 설치

2)설정
=>설정 파일 위치
Linux: /etc/redis/redis.conf
Mac: /opt/homebrew/etc/redis.conf
Windows: 설치된 디렉토리의 redis.windows-service.conf 

=>설정
- bind: redis를 사용할 수 있는 IP를 설정
127.0.0.1 하면 로컬에서만 접속 가능
0.0.0.0 하면 모든 곳에서 접속 가능

- port: 애플리케이션을 구분하기 위한 번호로 기본적으로 6379 이고 내부에서 redis끼리 통신하기 위해서 16379번을 사용

- protected-mode: 패스워드를 설정해야만 redis에 접근할 수 있도록 하는 설정으로 기본값은 yes

- requirepass / masterauth: 패스워드

- daemonize: 프로세스를 데몬으로 실행시키고자 할 때 사용하는 것으로 기본값은 no

- dir: 작업 디렉토리로 기본값을 ./(현재 디렉토리)

- tcp-backlog: 초당 클라이언트 연결 개수로 default는 511

- timeout: 클라이언트에서 서버 접속 시의 timeout 값으로 기본은 0

- maxclients: 최대 접속 가능한 클라이언트 수로 기본값은 10000

- tcp-keepalive: 클라이언트가 반응을 보이지 않을 때 서버가 접속을 제거하는 시간으로 기본값은 300

=>설정을 변경하면 Server를 다시 시작해야 적용됩니다.

3)접속
=>redis를 설지하면 redis-cli 라고 하는 접속 도구를 제공
바로 실행하면 로컬에 있는 redis 서버에 접속

=>원격 접속
redis-cli -h <IP주소> -p <포트번호> -a 패스워드
ip 주소를 생략하면 127.0.0.1 이고 포트번호 생략하면 6379

- Stream: 이벤트 로그를 저장하는 것으로 이를 이용해서 메시지 서비스를 제공

=>String
- 가장 간단하게 데이터를 저장할 수 잇는 구조
- 512MB까지 저장 가능
- 키와 데이터가 직접 연결되는 유일한 자료구조

- 숫자도 저장가능하고 숫자의 경우는 증감 연산이 가능
SET cnt 0

INCRBY cnt 50

- 여러 개를 저장하고자 할 때는 MGET 과 MSET 이용

=>List
- 하나의 키에 여러 개의 데이터를 저장하는 자료구조
- 하나의 list에는 43억개의 데이터를 저장할 수 있음
- 인덱스를 이용해서 데이터에 직접 접근하는 것이 가능
- 큐와 스택의 용도로 사용 가능
- 맨 앞과 맨 뒤에서 데이터를 삽입하고 꺼내는 것도 가능
- 삽입: LPUSH, RPUSH
- 범위 내의 데이터 조회: LRANGE key start stop
맨 끝에서부터 조회할 때는 -1, -2 형태의 음수를 사용
LRANGE mylist 0 -1
- 맨 끝의 데이터를 삭제하면서 조회: LPOP, RPOP
횟수도 설정 가능
- 범위를 제외하고 전부 삭제: LTRIM으로 사용법은 LRANGE 와 동일
LTRIM을 적절히 활용하면 고정된 길의 큐를 쉽게 유지할 수 있음
특정 개수의 로그 데이터를 유지하고자 하는 경우
LPUSH logdata <데이터>
LTRIM 0 99
항상 백개의 최신 로그가 유지됩니다.
- 중간에 데이터 삽입 가능: LINSERT
LINSERT 리스트이름 BEFORE 나 AFTER 기준값 추가할 값
- 데이터 수정: LSET
LSET 키 인덱스 값
- 특정 인덱스의 데이터 조회: LINDEX
- 특정 데이터 삭제: LREM

- 데이터 개수: LLEN 키

- 데이터 조회: SMEMBERS

=>HASH
- 하나의 키에 여러 개의 필드와 값을 가질 수 있는 자료구조
- 필드는 해시 내에서는 유일해야 합니다. 
- 생성 및 필드 추가 및 수정은 HSET
- 특정 필드의 값 가져오기는 HGET
- 여러 개의 필드의 값 가져오기는 HMGET
- 모든 필드 가져오기 HGETALL
- 모든 키 가져오기는 HKEYS
- 모든 값 가져오기는 HVALS
- 특정 키 삭제는 HDEL 

=>Sorted Set(ZSet)
- score 값에 따라 정렬되는 고유한 문자열의 집합
- 모든 아이템은 스코어 와 값 쌍을 가지며 저장될 때 부터 스코어 값으로 정렬돼 저장
- 스코어가 동일하면 데이터의 사전 순서대로 정렬
- list 와 sortedset 모두 순서를 갖는 자료구조라서 인덱스를 이용해서 아이템에 접근할 수 있음
인덱스를 이용한 접근 속도는 sortedset이 빠릅니다.
list는 Linked List로 라서 데이터의 접근 속도가 O(n) 이지만 Sorted Set은 Hash를 이용해서 인덱스를 저장하기 때문에 접근 속도가 O(log n)
- 데이터 저장은 ZADD 키 스코어 값 스코어 값...
- 옵션
XX
NX
LT: 업데이트하고자하는 스코어가 기존 아이템의 스코어보다 작을 때만 업데이트하고 없으면 추가
GT: 업데이트하고자하는 스코어가 기존 아이템의 스코어보다 클 때만 업데이트하고 없으면 추가

- 아이템 조회

이 때 BYSCORE 앞에 (를 추가하면 start 값은 제외

=>Bitmap
- STRING 자료구조에 bit 연산을 수행할 수 있도록 확장된 형태

=>Hyperloglog
- 집합의 원소 개수인 카디널리티를 추정할 수 있는 자료구조
- 대량의 데이터에서 중복되지 않는 고유한 값을 집계할 때 유용하게 사용할 수 있는 자료구조
- set 과 같은 데이터 구조에서는 중복을 피하기 위해 저장된 데이터를 전부 기억하고 있기 때문에 저장되는 데이터가 많아지면 메모리를 많이 사용

- 오차는 어느정도 발생
- 추가할 때는 PFADD를 이용하고 데이터 개수는 PFCOUNT
