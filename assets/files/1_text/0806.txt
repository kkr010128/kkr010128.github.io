2)네트워크 위협
=>세션 하이재킹
- Session: 웹이나 프로그램에서 사용자가 접속을 해서 활동을 마치고 떠날 때 까지의 하나의 연속된 연결 단위를 의미
웹 이나 IT 개발에서의 세션 - 상태 유지 기술
	HTTP 나 HTTPS는 비연결성 기술(Stateless - 상태를 기억하지 않음)
	요청을 보낼 때 잠시 연결되고 응답을 받으면 연결이 바로 끊기는 구조라서 이전 상태를 기억하지 못하기 때문에 작업의 연속성을 보장할 수 없음
	사용자의 로그인 상태 나 활동 정보를 서버 측에 저장해 유지하는 방식을 세션이라고 합니다.

	동작 방식
		사용자가 로그인에 성공하면 서버는 고유한 세션ID를 생성해서 서버 메모리(일반적인 방식)나 데이터베이스(최근에는 데이터베이스에 저장하는데 이 때 사용하는 데이터베이스 중 가장 많이 사용되는 것이 Redis)에 저장

		서버는 이 세션ID를 클라이언트에게 전달하고 클라이언트는 이를 Cookie(브라우저에 문자열을 저장할 수 있는 공간으로 서버에 요청을 할 때 무조건 같이 전송)에 저장

		클라이언트가 요청을 하면 세션ID를 포함시켜 요청을 전송

		서버는 세션ID를 확인해서 누구의 요청인지 알 수 있게 됩니다.

	세션을 Stateful 하다라고 하고 이 세션을 이용하는 대표적인 장비가 Firewall

데이터 분석이나 AI에서의 의미
	한 방문자가 사이트에 들어와서 일정 시간 동안 수행하는 모든 활동의 집합을 1개 세션으로 카운트

- 1995년에 케빈 미트닉이 시스템 관리자인 시모무라 쓰토무의 컴퓨터를 공격한 기법

- 두 시스템 간의 연결이 활성화된 상태 즉 로그인 상태를 가로채는 것이 세션 하이재킹 

- TCP 세션 하이재킹
공격자가 원하는 접속만 공격 대상이 생성하면 네트워크 공격으로 세션을 빼앗을 수 있음

로컬 세션 하이재킹 공격과 원격 세션 하이재킹 공격이 있음

로컬 세션 하이재킹은 공격 대상을 탐지할 수 있지만 원격 세션 하이재킹은 공격 대상을 탐지 불가능

클라이언트와 서버 간의 통신을 관찰할 수 있을 뿐 아니라 트러스트를 이용한 세션은 물론 텟넷, FTP 등 TCP를 이용한 거의 모든 세션을 갈취하는 것이 가능

인증에 관한 문제를 해결하기 위해 도입된 일회용 패스워드, 토큰 기반 인증을 이용한 세션 갈취도 가능

=>무선 네트워크 공격과 보안
- 무선 랜
유선 랜의 네트워크를 확장하려는 목적으로 사용

내부의 유선 네트워크에 AP 장비를 설치해야 함

확장된 무선 네트워크는 AP를 설치한 위치에 따라 통신 영역이 결정

보안이 설정되어 있지 않으면 공격자가 통신 영역 안에서 내부 사용자와 같은 권한으로 공격 가능

무선 랜의 전송 가능 길이는 수신 안테나의 형태에 따라 다르지만 짧게는 수십 m에서 길게는 1~2Km 까지도 가능

무지향성 안테나
	주로 봉의 형태이며 전파 수신에 일정한 방향성이 없어 AP의 위치에 상관없이 동작
	여러 방향을 지원하기 때문에 수평면에 무지향성

지향성 안테나
	수직 과 수평으로 나눔
	목표 방향을 지정하여 그 방향의 전파만 탐지하기 때문에 통신 거리가 더 긴 편
	쟁반 또는 접시 모양

- AP 보안
물리적인 보안 및 관리자 패스워드 변경
	AP는 전파가 건물 내에 한정되도록 전파 출력을 조정
	
	창이나 외부에 접한 벽이 아닌 건물 안쪽 중심부의 눈에 띄지 않는 곳에 설치
	
	설치 후에는 AP의 기본 계정과 패스워드를 반드시 재설정

SSID 브로드캐스팅 금지
	SSID: 무선 랜 네트워크 검색 시 확인할 수 있는 AP 목록 중 이름으로 표시된 것 

	무선 랜에서 AP의 존재를 숨기고 싶으면 SSID 브로드캐스팅을 막고 사용자가 SSID를 입력해야 AP에 접속할 수 있게 해야 합니다.

	높은 수준의 보안 권한이 필요한 무선 랜은 대부분 SSID 브로드캐스팅을 차단 

- 무선 랜 통신의 암호화
통신 과정에서 데이터 유출을 막는 것 뿐 아니라 네트워크에 대한 인증을 위해서도 암호화를 수행

암호화된 통신을 수행하는 네트워크에 접근을 시도하면 [네트워크 보안 키 입력] 창 나타남

WEP
	무선 랜 통신을 암호화하기 위해서 802.11b 프로토콜부터 적용
	RC4 암호화 알고리즘을 기본으로 사용
	
WEP을 이용한 암호화 세션
	사용하려는 무선 랜 서비스의 SSID 값을 알아내어 무선 랜 AP에 연결 요청 메시지를 전송

	사용자의 연결 요청 메시지를 받은 AP는 임의의 문장을 생성하여 원본을 저장하고 연결 요청 응답 메시지를 이용하여 암호화되지 않은 인증용 문자열을 전송

	인증용 문자열을 받은 사용자는 자신이 가진 공유 키로 WEP 암호화를 적용하여 암호문을 만든 다음 AP에 전송

	사용자가 공유 키로 만든 암호문을 전송받은 AP는 자신이 가진 공유 키로 암호문을 복호화

	복호화된 문장과 자신이 가진 원본 문장을 비교해서 같으면 사용자를 같은 그룹원으로 인식해 연결 허용 메시지를 전송

무선 랜 통신의 암호화
	WEP는 암호화 과정에서 암호화 키와 24비트의 IV를 사용

	통신 과정에서 IV는 랜덤으로 생성되어 암호화 키에 대한 복호화를 어렵게 하는 반면 짧은 길이의 24비트가 반복 사용되면서 WEP 키의 복호화를 쉽게 함

	무선 통신에서 네트워크 패킷에 포함된 IV를 충분히 수집하면 WEP키를 크래킹할 경우 1분이내에 복호화가 가능

	WEP 방식의 문제점을 해결하기 위해 만들어진 것이 WPA-PSK 와 EAP

3)보안 솔루션
=>인증 시스템
- 인증 수단
알고 있는 것
	사용자가 알고 있는 정보로 인증
	사용자의 아이디와 패스워드를 이용한 인증
	사용자의 기억에 의존하기 때문에 값싸고 편리하지만 패스워드를 안전하게 관리하기가 조금 어려움

본인
	지문
		가격 부담이 없고 효율성이 좋으며 사용 시 거부감이 없음
		손에 땀이 많거나 허물이 잘 벗겨지는 사람의 경우는 오탐률이 높음

	손 모양
		손가락의 길이나 굵기 등 손 모양을 이용하여 인증하는 방식
		매우 간편하고 인증 데이터의 크기가 작아서 빠른 인증이 가능
		손 모양이 비슷한 사람도 많고 고무 인형 등을 이용하여 쉽게 조작할 수 있어 높은 보안 수준을 제공하지 못함

	망막
		눈 뒷부분의 있는 모세혈관을 이용하는 것
		인증하는데 10~15초 정도 걸리고 정확도가 매우 높음 
		장치에 눈을 10초 이상 대고 초점을 맞춰야 하므로 거부감을 불러일으킬 수 있음
		안경을 쓰거나 눈병에 걸리면 인식률이 떨어짐
		매우 높은 보안 수준을 요구할 때 사용

	홍채
		홍채 인증은 망막 인증보다 정확도가 높음
		50cm 정도의 거리에서도 인증이 가능
		망막 인증이 홍채 인증으로 대체되고 있지만 망막 인식 장비와 마찬가지로 고가

	서명
		보안 수준이 그 다지 높지 않음

	키보드
		키보드를 누를 때 발생하는 특정한 리듬을 이용하여 신분을 확인하는 방법
		오탐률이 높아서 높은 보안 수준을 요구하는 경우에는 사용하지 않음

	성문
		사람마다 각기 다른 성문을 이용하는 인증
		성문은 환경이나 감정에 따라 변하기도 하고 흉내 낼 수 도 있어서 보안 수준이 높지 않음

	얼굴
		얼굴 사진을 이용하는 인증

가지고 있는 것
	사용자가 소유한 것을 인증 수단으로 사용
	다른 사람이 쉽게 도용할 수 있기 때문에 단독으로 쓰이지 않음

	스마트 키 또는 스마트 카드

	신분증: 가지고 있는 것과 자신의 모습을 모두 이용

	OTP
		1분 마다 다른 패스워드를 생성하는 단말장치
		고정된 번호 중에서 임의의 지시 번호를 입력하는 보안 카드보다 좀 더 안전한 방식

	공인인증서
		인터넷 뱅킹이나 온라인상의 신용카드 거래에서 많이 사용
		공인인증서 비밀번호를 알아야 하므로 가지고 있는 것 과 알고 있는 것을 동시에 이용하는 인증

위치하는 곳
	사용자 IP
		인터넷 게임이나 온라인 서비스를 할 때 국가에 따라 서비스 정책이 다른 경우 사용자 IP를 통해 국가 간 접속을 차단하는 것

	콜백
		발신자가 전화로 서비스를 요청했을 때 전화를 끊고 다시 걸려온 번호로 전화를 다시 걸어 발신자의 전화번호가 유효한지 확인

- SSO
모든 인증을 하나의 시스템에서라는 목적으로 개발

시스템이 몇 대라도 한 시스템에 인증에 성공하면 다른 시스템의 접근 권한을 모두 얻는 것

동작 방식
	클라이언트가 서버에 연결을 요청
	서버는 클라이언트에게 SSO 서버로부터 인증을 받은 후 접속하라고 요청
	클라이언트가 SSO 서버로부터 인증을 받음
	SSO 서버와 연결된 서버들에 별도의 인증 과정없이 접속할 수 있음
	
Kerberos
	윈도우 액티브 디렉터
	SSO, 서버, 클라이언트로 구분해서 사용

서비스 기반으로 SSO를 구현하는 경우
	사용자는 서비스가 관리하는 중앙의 패스포트 서버로 서비스 가입이나 인증 받음

	가맹 사이트는 패스포트 서버로 인증을 하므로 인증 시스템을 따로 구축할 필요가 없음
	
	패스포트가 가진 정보를 자동으로 채워주는 템플릿 기능도 제공

	웹 기반 SSO는 가입자의 인터넷 사용 정보를 효과적으로 얻을 수 있다는 이점때문에 사용률이 매년 증가

	동일한 인증 정보가 광범위한 서비스에서 사용되면 취약 포인트가 많아져 보안 측면에서 우려됨
	
	최초 인증 과정을 통과하면 모든 서버나 사이트에 접속할 수 있는 단일 장애점이 만들어짐

	약점을 보완하기 위해 중요 정보에 접근할 때는 지속적인 인증을 하도록 합니다.

=>DDoS 방어 장비
- DDoS 공격
DoS 공격은 Denial of Service 공격의 약자로 다양한 방법으로 공격 목표에 서비스 부하를 가해 정상적인 서비스를 할 수 없도록 하는 것

DoS 공격은 적이 공격 출발지에서 공격하는 것이 일반적이었으므로 비교적 탐지가 쉽고 짧은 시간에 탐지만 할 수 있다면 IP 주소 기반으로 충분히 방어할 수 있음

이런 탐지를 회피하고 더 짧은 시간에 공격 성과를 내기 위해서 다수의 봇을 이용해서 분산 공격을 수행하는 DDoS 공격 기법이 등장

- DDoS 방어 장비
DDoS 방어 장비는 볼류메트릭 공격(네트워크 대역폭을 고갈시키는 공격)을 방어하기 위해서 트래픽 프로파일링 기법을 사용하고 인터넷의 다양한 공격 정보를 수집한 데이터베이스를 활용하기도 함

동작 방식
	클라우드 서비스, 회선 사업자의 방어 서비스, DDoS 방어 장비를 사내에 설치하는 등이 있음
	회선 사업자 와 DDoS  방어 장비르 이원화 해서 방어하기도 함
	DDoS 공격을 탐지해서 공격을 수행하는 IP 리스트를 넘겨주면 방버 장비나 ISP 내부에서 이 IP를 버리는 것이 가장 흔한 DDoS 방어 기법

DDoS를 판별하는 방법
	프로파일링 기법 - 평소 데이터 흐름을 습득해 일반적인 대역폭, 초기 접속량, 프로토콜 별 사용량 등을 저장한 후 습득한 데이터와 일치하지 않는 과도록 트래픽인 인입되면 알려주고 차단하는 방식으로 습득한 데이터는 다양한 날짜 범위와 다양한 요소를 모니터링

	데이터베이스 기반 - IP 평판 데이터베이스를 공유해 DDoS 공격으로 사용된 IP 기반으로 방어 여부를 결정하거나 특정 공격 패턴을 방어하는 방법

- DDoS 공격 타입
Value Metric 공격
	대역폭을 포화시키는 공격
	쓸모없는 패킷이 회선을 모두 차지해서 정상적인 서비스 트래픽이 통과할 수 없도록 하는 것
	NTP 증폭, DNS 증폭, UDP 플러딩, TCP 플러딩
	DDoS 장비를 가지고 방어
	ISP 나 클라우드 서비스에서는 방어 체계가 구축되어 있어서 큰 투자없이 방어할 수 있음

프로토콜 공격
	공격 대상이나 중간 위험 리소스의 처리 용량을 모두 사용하도록 하는 것
	공격 대상 장비의 CPU, 메모리 자원을 고갈시키는 것
	네트워크 장비를 공격할 때 주로 이용
	Syn플러딩, Ping of Death
	클라우드 서비스를 이용하는 경우 네트워크 장비를 직접 설정하지 않기 때문에 ISP 나 CSP 가 해결

애플리케이션 공격
	대상 과의 연결을 설정한 후 프로세스 와 트랜잭션을 독점해서 서버 자원을 소모시키는 것
	서비스를 제공하는 플랫폼의 취약점을 악용
	HTTP 플러딩, DNS 서비스 공격, Slowloris

=>방화벽
- 방화벽은 4계층에서 동작하는 패킷 필터링 장비
- 4계층 정보를 기반으로 정책을 세울 수 있고 해당 정책과 매치되는 패킷이 방화벽을 통과하면 그 패킷을 허용(Allow, Permit)하거나 거부(Deny) 할 수 있음
- 방화벽은 일반적으로 DDoS 방어 장비 바로 뒤에 놓는 네트워크 보안 장비
- 3, 4 계층에서 동작하므로 다른 보안 장비보다 비교적 간단히 동작하고 성능도 우수
- 최근 출시되는 고성능 방화벽은 ASIC(Application-Specific Integrated Circuit: 특정 목적만 수행하도록 설계 및 제작된 반도체) 이나 FPGA(Field Programmable Gate Array - 사용자가 제작 후에도 회로를 자유롭게 변경할 수 있는 반도체) 같은 칩을 이용해 가속하므로 대용량을 요구하는 데이터 센터에서도 문제없이 사용 가능

=>칩입 탐지 시스템(IDS - Intrusion Detection System)
- 네트워크를 통한 공격을 탐지하기 위한 장비
- 내부의 해킹이나 악성 코드 활동 탐지와 같이 방화벽이 하지 못하는 일을 수행
- 설치 위치와 목적에 따라서 호스트 기반의 침입 탐지 시스템(HIDS) 와 네트워크 기반의 침입 탐지 시스템(NIDS)으로 구분
- 주요 기능
데이터 수집
- 호스트 기반의 IDS
윈도우나 유닉스 등의 운영체제에 부가적으로 설치해서 운용하거나 일반 클라이언트에 설치

운영체제에 설정된 사용자 계정에 따라 어떤 사용자가 어떤 접근을 시도하고 어떤 작업을 했는 지 기록을 남기고 추적

네트워크 환경과의 연계성이 낮아 전체 네트워크에 대한 침입 탐지가 불가능하고 자신이 공격 대상이 될 때만 침입 탐지 가능

운영체제의 취약점이 HIDS를 손상할 수 있으며 다른 침입 탐지 시스템보다 비용이 많이 드는 것이 단점

- 네트워크 기반의 IDS
네트워크에서 하나의 독립된 시스템으로 운용

감사와 로깅을 할 때 네트워크 자원이 손실되거나 데이터가 변조되지 않음

HIDS로는 할 수 없는 네트워크 전반에 대한 감시를 할 수 있으며 감시 영역이 상대적으로 큼

IP 주소를 소유하지 않아 해커의 직접적인 공격을 거의 완벽하게 방어할 수 있고 존재 사실도 숨길 수 있음

공격에 대한 결과를 알 수 없으며 암호화된 내용을 검사할 수 없음

스위치 환경에서 NIDS를 설치하려면 다른 부가 장비 필요\

10Gbps 이상의 고속 네트워크에서는 네트워크 카드 등의 하드웨어적인 한계로 네트워크의 모든 패킷을 검사하기 어려움

- 데이터 필터링 과 축약
HIDS 와 NIDS에 의해 수집된 침입 관련 데이터를 한 곳에 모아 관리하면 데이터를 상호 연관시켜 좀 더 효과적으로 분석함으로써 공격에 빠르게 대응할 수 있음

- 침입 탐지
오용 탐지 기법
	이미 발견되고 정립된 공격 패턴을 미리 입력해두었다가 해당하는 패턴이 탐지되면 알려주는 것
	비교적 오탐률이 낮고 효율적
	알려진 공격이외에는 탐지할 수 없고 대량 데이터를 분석하는 데는 부적합
	어떤 순서로 공격을 실시했는지에 대한 정보를 얻기 어려움

이상 탐지 기법
	정상적이고 평균적인 상태를 기준으로 급격한 변화를 일으키거나 확률이 낮은 일이 발생하면 알려주는 것
	인공지능 침입 탐지 시스템은 스스로 공격을 판단하고 결정을 내려 알려주지만 판단 근거가 확실치 않고 오탐률 높음
	면역 시스템은 새로운 공격을 당하면 스스로 학습하여 다시 그 공격이 발생하면 대응함

- 책임 추적 및 대응
예전에는 침입에 대한 능동적인 기능이 별로없고 공격을 발견하면 관리자에게 알람 등의 방법으로 알림  
최근에는 공격을 역추적하여 침입자의 시스템이나 네트워크를 사용하지 못하게 하는 능동적인 기능이 많이 추가
침입 방지 시스템(IPS): 능동적인 기능을 많이 탑재한 침입 탐지 시스템

- 침입 탐지 시스템 설치
라우터 앞에 설치 하는 경우 - 패킷이 라우터로 들어오기 전
	네트워크에 실행되는 모든 공격 탐지 가능
	공격 의도를 가진 패킷을 미리 파악할 수 있음
	공격이 아닌 패킷을 너무 많이 수집
	내부 네트워크 침입한 공격과 아닌 것이 구분되지 않아 효율적인 대응이 어려움

라우터 바로 뒤에 설치
	라우터의 패킷 필터링을 거친 패킷 검사
	패킷 필터링 과정에서 단순한 공격 패킷이 걸러지므로 더 강력한 의지를 가진 공격자 탐지 가능

방화벽 뒤
	네트워크에 직접 영향을 주므로 공격에 대한 정책과 방화벽 연동성이 가장 중요
	내부에서 외부로 향하는 공격도 탐지 할 수 있어서 내부 공격자도 어느 정도 탐지 가능
	침입 탐지 시스템을 한 대 만 설치 할 수 있다면 이곳에 설치하는 것이 좋음

내부 네트워크
	내부의 클라이언트를 신뢰할 수 없어서 내부 네트워크 해킹을 감시할려고 할 때

DMZ
	능력이 매우 뛰어나 외부 및 내부 공격자에 의한 중요 데이터의 손실이나 서비스 중단을 막기 함
	중요 데이터와 자원을 보호하기 위해서 침입 탐지 시스템을 별도로 운영

=>침입 방지 시스템(Instrusion Protection System)
- 개요
방화벽은 IP 주소나 포트에 의한 네트워크 공격을 차단할 수 있지만 응용 프로그램 수준의 공격과 새로운 패턴의 공격에 대한 적응력이 무적 낮고 실시간 대응을 할 수 없음

침입 탐지 시스템은 실시간 탐지는 가능하지만 대응책을 제시하지 못함

방화벽과 침입 탐지 시스템만으로 해킹, 바이러스, 웜 공격을 막을 수는 없음

- 침입 탐지 시스템 과 방화벽의 조합
수행하는 모듈이 패킷 하나 하나를 검사해서 분석
정상적이지 않으면 방화벽 기능의 모듈로 패킷 차단

- 설치
일반적으로 방화벽 뒤에 설치
방화벽없이 침입 방지 시스템만 설치하기도 함
하드웨어 칩으로 만든 ASIC을 소프트웨어로 많이 이용

=>WAF
- WAF(Web Application Firewall)은 웹 서버를 보호하는 전용 보안 장비로 HTTP 나 HTTPS 처럼 웹 서버에서 동작하는 웹 프로토콜의 공격을 방어
- IDS/IPS 장비보다 범용성은 떨어지지만 웹 프로토콜에서는 더 세밀히 방어할 수 있음
- WAF는 다양한 형태의 장비나 소프트웨어로 제공
전용 네트워크 장비
웹 서버의 플러그 인
ADC(Application Delivery Controller - L7 LoadBalancer) 플러그 인
프록시 장비 플러그인 
- IPS에서 방어할 수 없는 IPS 회피 공격을 방어할 수 있는데 IPS는 데이터를 조합하지 않고 처리하지만 WAF는 프록시 서버와 같이 패킷을 데이터 형태로 조합해서 처리하기 때문에 회피 공격을 쉽게 만들지 못하게 데이터의 일부를 수정 및 추가하는 기능을 수행할 수 있음
- 공격 트래픽을 방어만 하지 않고 공격자에게 통보하거나 민감한 데이터가 유출될 대 그 정보만 제거해 보내 줄 수 있음

=>샌드박스
- 기존에는 해커가 원하는 목적지에 직접 공격을 수행했음
보안 장비들이 발전하면서 해커들이 방화벽을 직접 뚫고 원하는 목적지로 공격하는 것이 점점 어려워짐
보안 장비들을 우회하는 기법들이 등장
- 악성 코드가 든 이메일을 관리자에게 직접 보내거나 관리자가 악성 코드를 내려받도록 다양한 방법으로 유도
코드를 내려받은 PC들을 외부에서 컨트롤하도록 C&C(Command & Control) 서버를 만들어 놓고 감염 PC들이 이 C&C 서버로 연결하도록 조작하는데 기존 방화벽에서는 내부 사용자가 외부 서버로 통신을 정상적으로 시도한 것으로 보이므로 이 공격을 검출하거나 방어할 수 없음
- 이러한 공격들이 발전해서 현재는 APT(Advanced Persistent Threat - 지능형 지속 공격) 와 ATA(Advanced Target Attack - 지능형 표적 공격)가 됨 
- 샌드박스는 APT의 공격을 방어하는 대표적인 장비로 악성 코드를 샌드박스 시스템 안에서 직접 실행시킴
가상 운영체제 안에서 각종 파일을 직접 실행시키고 그 행동을 모니터링해서 그 파일들의 악성 코드 여부를 판별
- 최근 악성 코드들은 다크웹에서 코드가 공개되거나 사고 팔리는 경우가 많아서 짧은 기간에 다양한 변종이 출현해 탐지하기 어렵고 기존 보안 시스템이 공격을 탐지하지 못하도록 암호화 또는 난독화하거나 여러 단계를 거쳐서 공격
파일을 직접 실행한 후 파일의 행동을 모니터링하면 이런 악성 코드를 감싼 많은 트릭을 제거하거나 탐지 할 수 있음

=>NAC
- Network Access Control은 네트워크에 접속하는 장치들을 제어하기 위해 개발
- 네트워크에 접속할 때 인가된 사용자만 내부망에 접속할 수 있고 인가받기 전이나 승인에 실패한 사용자는 접속할 수 없도록 제어하는 기술
- 내부 PC를 아무리 잘 관리하고 보안 패치를 신속히 수행하더라도 외부 PC가 내부망에 접속해 보안사고를 일으키거나 악성 코드를 전파하는 문제점들이 많이 발생하자 이것을 해결하기 위해 개발

=>IP 제어
- 보안사고 추적이 쉽도록 고정 IP 사용 권고 지침이 금융권에 내려오면서 IP를 추적하고 할당하는 솔루션이 필요하게 되었고 할당된 IP를 관리하고 정확히 의도된 IP 할당이 아니면 정상적으로 네트워크를 사용하지 못하게 하는 기능을 가진 IP 제어 솔루션

=>VPN
- 개요
Virtual Private Network의 약자

물리적으로 전용선이 아닌 공중망을 이용해 논리적으로 직접 연결한 것처럼 망을 구성하는 기술

논리적으로 직접 연결된 것처럼 만들어주는 통로를 Tunnel 이라고 하고 VPN을 이용하면 이 터널을 이용해 직접 연결한 것 처럼 동작

터널링 기법만 제공할 수 있다면 VPN 이라고 할 수 있지만 터널링만 제공하는 기법은 자주 사용되지 않고 VPN은 주로 인터넷과 같은 공중말을 전용선과 같은 사설망 처럼 사용하기 위해 도입하기 때문에 강력한 보안을 제공해야 해서 IPSEC, SSL 과 같은 암호화 기법을 제공하는 프로토콜을 VPN에 주로 사용

IPSEC는 주로 네트워크 연결용으로 사용하고 SSLVPN은 사용자가 내부 네트워크에 연결할 때 주로 사용

사용자 기반의 VPN 서비스를 제공해주는 장비를 VPN 장비라고 하는데 기존에는 별도의 VPN 서비스를 제공하는 하드웨어가 있었지만 현재는 대부분 방화벽이나 라우터 장비에 VPN 기능이 포함되어 있습니다.

전용 회선과 VPN
	인터넷 망이 아닌 전용 회선으로 직접 연결할 때도 전용 회선을 통해 VPN을 추가로 구성하는 경우가 있음
	전용 회선은 종단 간에 직접 연결하지만 회선자체에는 데이터가 그대로 흐르므로 암호화가 되어 있지 않은 상태라서 보안을 더 강화하기 위해서 전용 회선에 VPN을 추가호 구성해 데이터를 암호화하기도 함
	데이터 암호화는 VPN 장비가 아닌 애플리케이션에서 구현 가능

전용회선이 아닌 인터넷 망을 이용한 VPN
	회사 와 회사 처럼 네트워크 대 네트워크 연결에는 IPSEC VPN 기술을 사용
	개인 사용자가 네트워크에 접속하는 경우에는 SSLVPN 기술을 사용

- 최근에는 warning.or.kr 사이트를 우회하는 방법이나 특정 국가에서 결제해야 하는 상품 덕분에 다양한 VPN 서비스가 사용되고 있음
클라우드 방식으로 브라우저 익스텐션과 같은 편리한 방법으로 VPN 서비스를 제공하는데 IP 주소를 매우 쉽게 속이거나 해킹이 쉽지 않도록 패킷을 보호할 수 있음
단순히 사이트를 우회하는 기법으로 많이 사용되지만 카페와 같은 공중 무선망을 사용할 때 해커의 공격을 암호화 기법으로 원천 방어할 수 있어 공중 네트워크를 사용하는 경우 이런 VPN을 보안에 활용하는 것이 좋음

7.Firewall
1)개요
=>방화벽
- 신뢰하지 않는 외부 네트워크와 신뢰하는 내부 네트워크 사이를 지나는 패킷을 미리 정한 규칙에 따라 차단하거나 보내주는 기능을 하는 하드웨어나 소프트웨어

=>접근 제어
- 방화벽의 가장 기본적이고 중요한 기능
- 관리자가 통과시킬 접근과 거부할 접근을 명시하면 방화벽이 그에 따라 수행
- 구현 방법에 따라 패킷 필터링 방식 과 프록시 방식으로 나눔
- 접근 제어를 수행하는 룰셋은 방화벽을 기준으로 보호하려는 네트워크의 외부와 내부에 존재하는 시스템의 IP 주소와 포트로 구성
- 올바른 룰셋을 적용
허용할 서비스를 확인
제공하려는 서비스가 보안상 문제가 없는지, 허용하는 것이 타당한지 검토
서비스가 이루어지는 형태를 확인하고 어떤 룰을 적용할 지 구체적으로 결정
방화벽에 실제로 룰을 적용하고 적용된 룰을 검사

=>로깅 과 감사 추적
- 방화벽은 룰셋 설정과 변경, 관리자 접근, 네트워크 트래픽의 허용 또는 차단과 관련한 사항을 로그로 남김
- 사고 발생 시 출입자를 확인하여 추적을 하기 위함
- 인증
메시지 인증: VPN과 같은 신뢰할 수 있는 통신선으로 전송되는 메시지의 신뢰성을 보장

사용자 인증: 패스워드를 이용한 단순한 인증부터 OTP, 토큰 기반 인증 등 높은 수준의 인증까지 가능

클라이언트 인증: 모바일 사용자처럼 특수한 경우에 접속을 요구하는 호스트 자체가 정당한지 확인하는 방법
- 데이터 암호화
한 방화벽에서 다른 방화벽으로 데이터를 암호화해서 보내는 것
일반적으로 VPN의 기능을 이용

2)방화벽의 한계
=>바이러스 차단 불가
- 방화벽은 패킷의 IP 주소와 포트 번호로 접근 제어를 하는 것이 보통
- 좀 더 높은 수준의 접근 제어도 가능하지만 패킷의 데이터 내용 자체는 검사하지 않음

=>내부 공격 차단 불가: 방화벽은 경계에 대한 보안 정책을 수행할 뿐 내부 공격자에게 보안 정책을 적용할 수 는 없음

=>자신을 통과하지 않은 통신에 대한 제어 불가

=>새로운 형태의 공격 차단 불가

3)방화벽의 구조
=>Bastion Host
- 성곽의 모서리 둥근 부분을 지칭하는 독일어로 감시병이 횃불을 들고 올라가 성을 지키거나 공격해오는 적을 방어하기 위한 최상의 위치를 의미
- 네트워크에서의 배스천 호스트는 철저한 방어 정책이 구현되어 있고 외부 접속에 대한 일차적인 연결을 받아들이는 시스템
- 배스천 호스트 위치 중의 한 곳에 방화벽이 놓임

인터넷 <-> Public Subnet 안에 배스천 호스트 컴퓨터 <-> 각각의 서버

=>Screening Router
- 일반 라우터에 패킷 필터링 규칙을 적용한 방화벽
- 외부 네트워크와 내부 네트워크의 경계에 높임
- IP 주소와 포트에 대한 접근 제어만 가능

내부 네트워크 <-> 스크리닝 라우터 <-> 인터넷

=>단일 홈 게이트웨이 
- 스크리닝 라우터보다 좀 더 발전한 형태의 방화벽
- 일반적으로 이 구조를 베스천 호스트라고 부르기도 함
- 접근 제어, 프록시, 인증, 로깅 등과 같은 방화벽의 가장 기본이 되는 기능을 수행
- 단일 홈 게이트웨는 반드시 아래 작업을 수행
일반 사용자 계정을 모두 삭제
방화벽 기능 외의 유틸리티와 파일은 모두 지움
대용량의 모니터링과 로깅이 가능해야 함
IP 포워딩 및 소스 라우팅 기능을 없앰
- NIC가 하나인 경우

내부 네트워크 <-> 단일 홈 게이트웨이 컴퓨터 <-> 인터넷

=>이중 홈 게이트웨이
- 네트워크 인터페이스 카드를 2개 이상 갖춘 방화벽
- 내부 네트워크에서 인터넷을 이용하거나 인터넷에서 내부 네트워크가 제공하는 서비스를 이용하려면 이 구조로 만들어야 함

내부 네트워크 <-> 이중 홈 게이트웨이 컴퓨터 <-> 인터넷
인터넷 과 연결되는 네트워크 인터페이스 카드와 내부 네트워크와 연결되는 네트워크 인터페이스 카드가 다름

=>스크린된 호스트 게이트웨이
- 라우터 와 방화벽을 구분해 운영하는 방화벽
- 스크리닝 라우터와 단일 홈 게이트웨이의 조합으로 운영하는데 이중 홈 게이트웨이도 가능

모든 장비가 라우터에 연결되지만 라우터로 패킷을 전송하지 못하고 단일 홈 게이트웨이를 거쳐서 라우터에 데이터를 전달하고 전달받을 수 있는 구조입니다.

=>스크린된 서브넷 게이트웨이
- 외부 네트워크 와 내부 네트워크 사이에 완충지대를 두는 방화벽
- 다른 방화벽의 장점을 모두 갖추고 있으면 융통성이 아주 뛰어남
- 설치와 관리가 어렵고 서비스 속도가 느리며 비용도 많이 듬

인터넷 <-> 스크리닝 라우터 <-> 단일 홈 게이트웨이 <->스크리닝 라우터 <-> 내부 네트워크

4)ACL
=>개요
- 네트워크에서는 라우터가 트래픽 연결점 역할을 수행
- 라우터에서 Access Control List를 사용하여 트래픽 식별, 필터링, 분류, 변환 작업을 수행

=>동작
- ACL의 허용 또는 거부 동작은 입력 ACL(Inbound ACL) 과 출력 ACL(OutBound ACL) 2가지 방식으로 이루어짐
- 입력 ACL은 패킷들이 라우팅되기 전에 처리
- 출력 ACL은 패킷들이 라우팅 테이블을 참조해서 라우팅 된 후 패킷의 허용 및 거부를 결정
- ACL은 여러 인터페이스에 적용 가능
- 하나의 인터페이스에서는 하나의 입력 과 출력 ACL을 설정
- 하나의 프로토콜에는 하나의 ACL 만 적용
- 위에서부터 아래로 각각의 구문을 빠짐없이 패킷에 적용하여 검사하는데 순서대로 검사
- 서브넷 마스크 대신에 와일드 마스크 이용
=>종류
- 표준 ACL: 패킷의 발신지 IP 주소를 검사해서 패킷을 필터링 
- 확장 ACL: 패킷의 발신지와 목적지를 모두 검사
- 번호 ACL: ACL에 번호를 붙여서 사용
번호 ACL은 번호에 따라 표준과 확장이 결정되어 있습니다.
1~99, 1300~1999 번까지는 표준 ACL
100~199, 2000~2699 번 까지는 확장 ACL
- 이름 ACL: ACL에 이름을 붙여서 사용

=>3대의 라우터가 통신이 가능하도록 설정
- 3대의 라우터 배치

- 3대를 연결(R1 과 R2는 Ethernet2/0 R2 와 R3는 Ethernet2/1) 

- 3개의 라우터에 통신이 가능하도록 설정

R1#configure terminal

=>표준 ACL 작성
- 작성 방법
Router(config)# access-list 번호 {permit | deny | remark}  source wildmask

인터페이스로 접속
Router(config-if)#ip access-group 번호 {in | out}

- R3에서 192.168.1.1에 접속이 안되도록 적용
R3(config)# access-list 1 deny 192.168.1.1 0.0.0.0

R3(config)# interface ethernet2/1
R3(config-if)# ip access-group 1 out
R3(config-if)# ip access-group 1 in

- R3에서 ping
R3#ping 192.168.1.1
데이터가 전송되지 않습니다.

- R1에서 ping
R1#ping 192.168.2.1
UUUUU
가 출력되는데 방화벽에 막힌 것을 의미

=>확장 ACL
- 작성 방법
access-list 번호 {permit | deny} 프로토콜(ip/tcp/udp 등) 소스 와일드마스크 [operator 포트번호] 목적지 와일드마스크 [operator 포트번호]

192.168.2.1 에서 192.168.1.1로 가는 모든 통신을 거부
access-list 101 deny ip 192.168.2.1 0.0.0.0 192.168.1.1 0.0.0.0 

모든 통신을 허용
access-list 101 permit ip any any

- 적용 방법은 표준 ACL 과 동일

=>ACL 작성 시 주의할 사항
- ACL은 하나의 번호에 여러 개 작성 가능
- 먼저 작성한 것이 적용되면 뒤의 것은 무시 됩니다.
- ACL을 작성하면 마지막에 무조건 deny ip any any 가 추가됩니다.
- 특정 네트워크만 막으려고 하는 경우에는 반드시 마지막에 permit ip any any를 추가해야 합니다.
