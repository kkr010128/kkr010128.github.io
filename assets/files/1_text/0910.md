=>로컬 저장소 생성: git init

- 화면에서 생성 버튼을 누르고 디렉토리를 선택한 후 저장소 이름 과 종류를 선택

=>첫번째 버전 생성
- 버전을 관리할 대상을 생성

- 파일을 선택하고 스테이지 영역으로 이동: git add

- Local Repository로 이동: git commit
commit을 할 때는 반드시 메시지를 작성해야 합니다.
첫번째 줄은 변경한 내역을 간단하게 설명하고 빈 줄을 삽입하고 실제 변경한 이유와 자세한 설명을 다음 줄에 입력 
커밋 메시지를 작성하고 커밋 버튼을 누르면 새로운 버전이 생성된 것

=>새로운 커밋 만들기
- c.txt 파일을 삭제하고 a.txt 파일을 수정

- 변경된 파일을 선택하고 스테이지 영역으로 이동: git add

- Local Repository로 이동: git commit

- History를 확인해보면 트리 형태로 어디서 분기를 했는지 확인이 가능

=>변경 내용을 추적하는 파일을 tracked 라고 하고 그렇지 않은 파일을 untracked 라고 합니다.

=>.gitignore: 
- 변경 사항을 추적하고 싶지 않은 파일이나 디렉토리를 등록하는 파일
- 변경사항이 발생해도 추적하지 않음
node 프로젝트는 자동으로 .gitignore가 생성되서 패키지 디렉토리를 제외를 시킵니다.
spring boot 프로젝트의 경우도 .gitignore는 자동으로 생성됩니다.

python의 가상환경을 사용하는 경우는 .gitignore가 생성되지 않습니다.
잘못하면 모듈이 업로드가 되는 경우가 있는데 이 경우 파일의 개수가 너무 많아서 push가 되지 않을 수 있습니다.

3)버전 관리 활용
=>버전 비교
- 직전 버전과 비교하는 것은 commit을 선택하면 됩니다.
- 다른 버전과 비교할 때는 버전을 선택하고 CTRL 키를 누른 채 다른 버전을 선택하면 하단에 변경된 파일들이 보이고 파일을 클릭하면 변경된 내용이 표시됩니다.

=>버전 되돌리기
- 스테이지에 올라간 파일 되돌리기: 스테이지 영역에서 - 버튼만 클릭

- 스테이지에 올라가지 않은 파일 되돌리기: 파일을 선택하고 초기화 나 폐기를 클릭

=>작업 되돌리기
- 커밋한 내용 되돌리기
revert: 버전을 되돌리는데 실제로는 되돌아간 상태를 가지고 새로운 버전을 추가하는 것, 기존의 버전은 삭제되지 않음
	기존의 버전이 남아있으므로 다시 돌아갈 수 있습니다.

reset: 돌아갈 버전의 시점으로 완전하게 되돌아가는 방식
	soft reset: 작업 디렉토리 내 변경 사항과 스테이지 추가된 변경 사항은 유지하되 커밋했다는 사실만 reset
	              commit 작업한 것만 취소, 상태는 마지막 상태 그대로

	mixed reset: 스테이지 와 커밋을 되돌리는 reset
		     add 작업한 것 까지 취소, 상태는 마지막 상태 그대로

	hard reset: 작업 디렉토리 내 변경 사항까지 전부 되돌리는 reset
		
=>stash로 작업 임시 저장
- 작업 디렉토리에서 생성한 모든 변경사항을 임시 저장하고 작업 디렉토리는 변경 사항이 생기기 전의 상태로 돌아감	
- add 작업을 수행한 후 add 작업을 취소하지 않고 현재 구조는 add 상태 이전으로 돌아가고 add 한 내용을 임시로 저장하는 것

4)브랜치
=>개요
- 버전을 여러 흐름으로 나누어 관리하는 방법
- branch는 버전의 분기

=>HEAD & Checkout
- HEAD
현재 작업 중인 브랜치의 최신 커밋을 가리키는 일종의 표시
브랜치를 나누고 합치는 과정에서 HEAD의 위치를 자유자재로 변경이 가능 

- Checkout
특정 브랜치에서 작업할 수 있도록 작업 환경을 변경하는 것
특정 브랜치로 체크아웃하게 되면 HEAD의 위치가 해당 브랜치의 최신 커밋을 가리키고 작업 디렉토리는 체크아웃한 브랜치의 모습으로 바뀜

=>브랜치 생성
- 상단의 브랜치를 누르고 브랜치 이름을 입력하고 사본을 제작할 커밋을 선택하고 체크아웃은 작업을 새로운 브랜치에서 수행할 것이라면 체크하고 생성 버튼을 누르면 됩니다.

=>브랜치 삭제: 브랜치를 선택하고 마우스 오른쪽 눌러서 삭제가 가능하지만 현재 사용 중인 브랜치는 삭제가 안됨

=>브래치 병합: 2개의 브랜치를 합쳐서 새로운 버전을 만들어 내는 것
- 병합을 할 때는 원본 브랜치로 체크 아웃을 한 후 병합할 브랜치를 선택하고 병합을 하면 됩니다.
- fast-forward merge
	기본적인 병합 방법으로 뻗어나온 시점부터 병합되는 순간까지 원본 브랜치에 어떤 변화도 없는 상태에서의 병합
	foo 브랜치는 main 브랜치에서 뻗어나왔는데 main 브랜치에 변화가 없었기 때문에 이 경우가 fast-forward merge
	로컬 repository에서 원격 repository로 push를 한 후 원격 레포지토리에 변화를 준 상태에서 로컬 repository에 변화를 준 후 push를 하면 fast-forward merge 에러 메시지가 보임 

- 특정 커밋으로 병합 가능

=>충돌
- 서로 다른 브랜치에서 동일한 파일을 수정한 경우
- 어떤 브랜치의 내용을 반영할 지 판단
- 현재 브랜치의 내용으로 할 것인지 아니면 병합되는 브랜치의 내용을 적용할 것인지 결정

=>rebase
- 브랜치를 재배치
- 뻗어나온 기준점을 변경하는 것이 rebase
- base 브랜치를 복제를 해서 새로운 브랜치를 만들어서 작업을 하고 있는 도중 base 브랜치에 변경이 생긴 경우 수행
새로운 브랜치와 base 브랜치에서 동일한 파일을 수정한 경우라면 rebase 도 충돌
=>재배치하고자 하는 브랜치로 체크아웃 한 후 rebase 하고 싶은 커밋을 선택하고 마우스 오른쪽을 누른 후 재배치를 수행

3.CLI 이용 - 명령어 기반
1)버전 생성
=>git init
- 디렉토리 안에 .git 이라는 디렉토리가 생성됨
- git 과의 연동을 해제하는 것은 .git 이라는 디렉토리를 삭제하면 됨

=>git status
- 현재 상태를 확인
On branch main: 현재 브랜치

No commits yet: 변경된 내용이 있는데 커밋을 하지 않음

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        1.txt

=>git add 
- stage 영역에 추가하는 명령
- git add 추가할 파일이나 디렉토리 경로를 나열
- git add .을 이용하면 현재 디렉토리의 모든 내용을 이동

=>git commit
- Local Repoistory에 staging 영역의 내용을 반영
- 기본 형식은 git commit -m "메시지"
- 메시지를 생략하면 메시지를 입력할 수 있는 창이 열림
- m 옵션은 여러 번 사용 가능

=>커밋 목록 보기
- git log

=>스테이지에 올리는 것 과 커밋을 동시에 수행
- git commit -am "메시지"
- tracked 된 파일만 commit이 적용

=>커밋을 단순하게 조회: git log --oneline

=>변경된 내용을 확인: git log --patch

=>그래프 형태로 조회: git log --graph

=>모든 브랜치의 커밋을 확인: git log --branches

2)태그 관리
=>태그 추가
- 현재 커밋에 태그를 추가: git tag <태그>
git tag v1.0.0

확인: git log

- 특정 커밋에 태그를 추가: git tag <태그> <커밋>
커밋의 해시를 알기 위해서 확인: git log --oneline

git tag v0.0.1 커밋의해시

=>태그 목록만 조회: git tag --list

=>태그 삭제: git tag --delete 태그

3)버전 비교
=>현재 작업 디렉토리와 최근 커밋 비교
- git diff

=>현재 스테이지 와 최근 커밋 비교
- git diff --staged

=>커밋 간의 비교
- git diff <기준 커밋> <변경된 커밋>
- 커밋을 기재할 때 HEAD를 사용하면 현재 기준 커밋입니다.
- HEAD^ 는 헤드 이전 커밋 HEAD^^ 헤드에서 두번째 이전 커밋이고 ^ 대신에 ~인덱스도 가능

=>브랜치 간의 비교도 가능
- git diff <브랜치이름><브랜치이름>

4)작업 되돌리기
=>soft reset: 커밋만 이전으로 되돌리기
git reset --soft <되돌아갈 커밋>

- 현재 작업 디렉토리 확인
- stage 영역을 확인: git diff --staged

=>mixed reset: 커밋 과 스테이지 영역을 되돌리기
git reset <되돌아갈 커밋>

- 현재 작업 디렉토리 확인
- stage 영역을 확인: git diff --staged

=>hard reset: 작업 디렉토리까지 되돌리기
git reset --hard <되돌아갈 커밋>

- 현재 작업 디렉토리 확인

=>예전 커밋으로 되돌리는 새로운 커밋 생성
git revert <최소할 커밋>
- reset은 되돌아갈 커밋을 기재하지만 revert는 최소할 커밋을 기재

5)stage 영역
=>stage 영역을 임시 저장: git stash

=>stage 영역 저장된 내역: git stash list

=>저장된 stage 영역으로 되돌리기: git stash apply <이름>

=>저장된 영역 삭제: git stash drop 이름(stash@{인덱스})

6)branch 작업
=>브랜치 생성: git branch <이름>

=>브랜치 변경: git checkout <이름>

=>브랜치를 만들면서 체크아웃: git checkout -b <이름>

=>브랜치 병합: git merge <병합할 이름>

=>브랜치 삭제: git branch -d <이름>

=>브랜치 재배치: git rebase <이름>

git hub action & git hub deployment API: CI & CD 기능
Project Boards: 협업 관리 기능
정적 웹 페이지 배포

2)현재 컴퓨터와 연결
- git hub에서 Personal Access Token을 발급받아서 등록
로그인은 다시 할 필요가 없지만 계정을 변경하고자 하는 경우 증명서를 삭제해야 함

토큰 발급: <GITHUB_PAT>

토큰 등록
	windows: git config --global credential.helper manager 또는 manager-core
	Mac OS: git config --global credential.helper osxkeychain

- git hub CLI 도구인 gh를 이용해서 로그인
gh logout으로 로그아웃 하고 다시 gh login으로 로그인을 하면 됩니다.

=>pull: 원격 저장소를 가져와서 합치기
