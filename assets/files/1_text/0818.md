6.도커 네트워크
1)개요
=>도커 컨테이너는 기본적으로 외부와 격리가 되어있는데 다른 컨테이너와 통신을 할 수 있도록 해주는 매커니즘
=>Docker Network의 하위 시스템 연결을 위해 Docker Network Driver를 사용
=>Docker를 설치하게 되면 기본적으로 제공되는 docker0라는 소프트웨어 적으로 구현된 가상 이더넷 브릿지 네트워크를 이용해서 통신
=>모든 컨테이너는 기본적으로 docker0 브릿지에 연결되어 172.17.0.0/16 의 CIDR(Classless Domain Routing) 범위로 IP 주소가 할당
=>네트워크 인터페이스 카드
- enp0s8
Ubuntu의 리눅스 네트워크 카드로 VirtualBox에서 제공하는 IP 주소를 할당받아서 사용 중
이름은 설치한 운영체제에 따라 다름

- docker0
도커를 설치할 때 만들어지는 브릿지 네트워크
이 브릿지 네트워크가 컨테이너 DHCP 형태로 IP를 할당

- eth0
docker 컨테이너에 생성되는 네트워크 인터페이스 카드
docker0를 게이트웨이로 해서 순차적으로 IP가 할당받거나 사용자가 동일한 대역의 IP 주소를 지정할 수 있음

vethXXXXXXXX:eth0 와 쌍으로 생성되는데 docker0와 가상의 터널링 네트워크를 ㅈ공

7.Dockerfile
1)IaC(Infrastructure as Code, IaC)
=>수동으로 배포했을 때의 발생할 수 있는 문제점
- CLI 기반의 인프라 구성 시 사용자 실수 등의 인적 오류 가능성이 높은데 APM(Apache + PHP + MySQL)을 구성하는 경우 설치 순서와 상호 연관성을 고려해 각종 라이브러리와 함께 복잡한 명령어를 고민해야 함
워드프레스의 경우 MySQL 이나 Maria DB가 구동 중이 아니면 설치도 안되고 실행도 안됨
- 각종 환경 설정 정보와 설치 프로그램을 요구사항에 맞게 살펴봐야 하는데 만일 설치 이후에 잘못된 설정이 있으면 수정해야 하고 때로는 재설치도 불가피
=> 이에 대한 해결책이 IaC
 
2)Dockerfile 의 개요
=>Docker Image를 생성하기 위한 스크립트(설정 파일)
=>장점
- 이미지를 어떻게 만들었는지를 기록
- 배포에 용이
- 이미지가 컨테이너로 생성될 때 특정 행동을 수행하도록 할 수 있음

3)작성 명령어
=>FROM
- 필수 항목으로 베이지 이미지를 지정
- hub.docker.com에서 제공하는 이미지를 권장
- 태그를 선택할 때는 작은 크기의 이미지(slim) 와 리눅스 배포판 인 알파인(apline) 이미지를 권장하지만 모든 애플리케이션이 동일하지는않음
- 태그를 생략하면 latest
- 예시
FROM ubuntu:20.04
FROM python:3.9-slim-buste

=>MAINTAINER
- 이미지를 빌드한 작성자 이름과 이메일을 작성
- 예시
MAINTAINER adam.park itstudy@kakao.com

=>LABEL
- 이미지 작성 목적을 나열하는데 버전, 타이틀, 설명, 라이선스 정보를 작성
- 여러 개 작성 가능
- 예시
LABEL version='1.0'
LABEL description='web service'

=>RUN
- 설정된 기본 이미지에 패키지 업데이트, 각종 패키지 설치, 명령 실행 등을 작성
- 여러 개 작성 가능
- 권장 사항
다단계 빌드 사용
RUN 명령어 별로 레이어가 생성되므로 레이어의 개수를 줄이기 위해서 여러 설치 명령을 연결해서 사용
autoremove, autoclean, rm -rf /var/lib/apt/lists/*을 사용해서 apt 캐시를 삭제: 이미지 크기 감소
- 사용 방식은 exec 방식 과 shell 방식
- exec 방식
RUN ["/bin/bash", "-c", "apt update"]
RUN ["/bin/bash", "-c", "apt -y install nginx git vim curl"]
- Shell 방식
RUN apt update && apt install -y nginx \
git \
vim \
curl \
apt clean -y && \
apt autoremove -y && \
rm -rfv /tmp/* /var/lib/apt/lists/* /var/tmp/*

=>CMD
- 생성된 이미지를 컨테이너로 만들 때 실행하는 명령이고 ENTRYPOINT 명령문으로 지정된 커맨드에 디폴트로 넘길 파라미터를 지정할 때 사용
- 여러 개의 CMD를 작성해도 마지막 하나만 처리
- 이미지를 가지고 컨테이너를 실행할 때 애플리케이션 데몬이 실행되도록 하는 경우 사용
- 사용 예
CMD["/usr/sbin/apachectl", "-D", "FOREGROUND"]
CMD apachectl -D FORGROUND

CMD ["nginx", "-g", "daemon off;"]

CMD ["python", "app.py"]

=>ENTRYPOINT
- CMD와 마찬가리조 생성된 이미지가 컨테이너로 실행될 때 사용되지만 컨테이너가 실행될 때 명령어 및 인자 값을 전달하여 실행한다는 점이 다름
- 여러 개의 CMD를 사용하는 경우 ENTRYPOINT 와 같이 사용
- ENTRYPOINT에 커맨드를 지정하고 CMD는 기본 명령을 지정하면 탄력적으로 이미지를 실행할 수 있음
- python 명령을 기본으로 runapp.py를 실행하고자 할 때
ENTRYPOINT ["python"]
CMD ["runapp.py"]
- 동일한 환경에 entrypoint.sh 셀 스크립트를 이미지에 넣고 실행 권한 설정한 후 컨테이너를 실행할 때 entrypoint.sh 파일을 실행
ADD ./entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
ENTRYPOINT ["/bin/bash", "/entrypoint.sh"]
- ENTRYPOINT는 Docker 컨테이너 실행 시 항상 수행해야 하는 명령어를 지정하고 CMD는 Docker 컨테이너 실행 시 다양한 명령어를 지정하는 경우 유용

=>COPY
- 호스트 환경의 파일을 이미지 안에 복사하는 경우 작성
- 빌드 작업 디렉토리 외부의 파일은 COPY 할 수 없음
- 예시
COPY index.html /usr/share/nginx/html
COPY ./runapp.py /

=>ADD
- 호스트 환경의 파일, 디렉토리를 이미지 안에 복사하는 경우 뿐 만 아니라 URL 주소에서 직접 다운로드 받아서 넣을 수 도 있고 압축 파일인 경우는 지정한 경우로 압축을 풀어서 추가
- 예시
ADD index.html /usr/share/nginx/html
ADD URL /workspace/data/

=>ENV
- 이미지 안에 각종 환경 변수를 지정하는 경우 사용
- 애플리케이션 사용을 쉽게 하기 위해 사전에 구성되어야 하는 환경 변수들이 있는 경우 사용
- 자바 홈 디렉토리, 특정 실행 파일의 경로를 보장하기 위해 절대 경로를 지정하기 위한 PATH 설정, 프로그램 버전 등을 사전에 설정
- Dockerfile에서 ENV를 설정하면 RUN, WORKDIR 등에서 환경 변수를 사용해 반복을 피할 수 있음
- 반복된 표현이 사용되는 경우에도 환경 변수 설정을 권장
- 사용 예시
ENV JAVA_HOME /usr/lib/jvm/java-8-oracle

=>EXPOSE
- 컨테이너가 호스트 네트워크를 통해 들어오는 트래픽을 listening 하는 포트와 프로토콜을 지정하기 위해서 작성
- docker run을 할 때 -p 에 설정해서 외부와 연결
- 예시
EXPOSE 80
EXPOSE 80/tcp

=>VOLUME
- 볼륨을 이미지 빌드에 미리 설정하는 경우에 작성
- VOLUME으로 지정된 컨테이너의 경로는 볼륨의 기본 경로인 /var/lib/docker 와 자동으로 연결
- 사용 예시
VOLUME /var/log
VOLUME /var/www/html

=>USER
- 컨테이너의 기본 사용자는 root
- 애플리케이션이 권한없이 서비스를 실행할 수 있다면 USER를 통해 다른 사용자로 변경해서 사용
- 예시
RUN ["useradd", "adam"]
USER adam
RUN ["/bin/bash", "-c", "date"]

=>WORKDIR
- 컨테이너 상에서 작업할 경로를 전환할 때 사용
- WORKDIR을 설정하면 RUN, CMD, ENTRYPOINT, COPY, ADD 명령문은 해당 디렉토리를 기준으로 실행
- 지정한 경로가 없으면 자동 생성되고 컨테이너 실행 이후 컨테이너에 접속하면 지정한 경로로 연결
- 사용 예
WORKDIR /workspace

=>ARG
- docker build 시점에서 변수의 값을 전달하기 위해 --build-arg=인자를 정의해서 사용
- 비밀키, 계정 비밀번호 같은 민감한 정보 사용 시 이미지에 직접 작성하면 외부로 노출될 위험이 있어서 빌드할 때 대입해서 사용
- 사용 예시
Dockerfile에 ARG 변수를 정의: ARG db_name
빌드를 할 때 docker build --build-arg-arg db_name=itstudy
입력받은 변수의 값을 사용할 때: CMD  db_start.sh -h 127.0.0.1 -d {$db_name}

=>ONBUILD
- 처음 이미지 빌드에는 사용하지 않지만 해당 이미지가 다른 이미지의 기본 이미지로 사용되는 경우 실행될 명령어를 지정할 때 사용

=>STOPSIGNAL
- docker stop 명령은 컨테이너에게 SIGTERM을 보내 정지시킴
- 다른 시그널을 보내고자 할 때
STOPSIGNAL SIGKILL(시그널 번호 또는 이름)

=>SHELL
- Dockerfile 내부에서 사용할 기본 셸을 지정하는 경우 작성
- 사용 예시
SHELL ["/bin/bash", "-c"]

=>HEALTHCHECK
- 컨테이너의 프로세스 상태를 체크하고자 하는 경우 사용
- 하나의 명령만이 유효하고 여러 개 지정된 경우 마지막에 선언된 것만 적용
- 옵션
--interval=초: 헬스 체크 간격으로 기본값은 30s
--timeout=초: 타임 아웃으로 기본값은 30s
--retries=숫자: 타임 아웃 횟수로 기본값은 3
- 상태 코드
0: 컨테이너 정상 작동
1: unhealty(컨테이너가 올바르게 작동하지 않는 상태)
2: strating(예약된 코드)

- 사용 예
1분마다 CMD에 있는 명령을 수행해서 3초 이상이 소요되면 한 번의 실패로 간주하고 5번 실패하면 unhealthy로 변경
HEALTHCHECK --interval=1m --timeout=3s --retries=5 CMD curl -f http://localhost || exit 1 

4)Dockerfile 명령어 작성 방법
=>시작은 FROM 명령부터 작성하고 다음 부터는 순서가 없지만 명령 순서는 빌드 캐시의 무효화와 관련되기 때문에 변경 빈도수가 적은 명령을 먼저 배치하는 것을 권장
=>도커 허브에는 많은 이미지가 존재하는데 무조건 OS 이미지를 선택하고 설치하는 것보다는 원하는 애플리케이션 패키지가 이미 설치된 이미지 선택을 권장하는데 이유는 이미지 관리의 유지보수 측면에서 시간 절약에 도움이 됨

5)이미지 빌드 명령
docker build [옵션] 이미지이름[:태그] Dockerfile 경로 | URL | 압축파일
=>옵션
t: 태그를 지정하고자 하는 경우
f: Dockerfile 아니라 다른 이름을 사용한 경우 이름을 지정

=>경로
- 디렉토리 단위로 개발하는 것을 권장: 디렉토리에 하나의 Dockerfile 만 존재하기를 권장
- 현재 디렉토리이면 .을 사용
- git hub 같은 분산 버전 관리 시스템을 사용하는 경우에는 URL로 입력
docker build -t phpserver:2.0 github.com/brayanlee/docker-phpserver

- 압축 파일에 있는 경우
docker build -f 압축파일경로

6)아파치 웹 서버에 메인 페이지를 변경하는 이미지
=>작업 디렉토리를 생성

=>메인 페이지로 사용할 html 파일을 생성(index.html)
<html>
    <head>
        <title>Docker Image Build</title>
    </head>
    <body>
        <h1>Apache Web Server</h1>
    </body>
</html>

=>Dockerfile 작성
FROM httpd
COPY index.html /usr/local/apache2/htdocs

=>이미지 빌드
docker build -t apacheex .

=>이미지 확인
docker images

=>새로 만들어진 이미지를 가지고 컨테이너를 생성
docker run --name apacheex -d -p 8000:80 apacheex 

=>컨테이너 생성 여부를 확인하고 포트 개방 여부를 확인
