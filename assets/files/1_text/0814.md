** Docker
1.Docker
1)Container 와 가상화
=>가상화
- 물리적 시스템에 대한 가상 표현을 생성하는데 사용할 수 있는 기술: 추상화
- 가상화 소프트웨어는 물리적 하드웨어 기능을 모방하여 하나의 물리적인 컴퓨터에서 여러 가상 시스템을 동시에 실행
- 기업은 가상화를 통해 하드웨어 리소스를 효율적으로 사용하여 투자 대비 이익을 더 많이 얻을 수 있고 클라우드 컴퓨팅 서비스를 지원하여 조직의 인프라를 더욱 효율적으로 관리할 수 있음

=>가상화 이점
- 효율적인 리소스 사용
- 자동화된 IT 관리
- 신속한 재해 복구

=>가상화 서비스
- 서버 가상화
- 스토리지 가상화
- 네트워크 가상화
SDN(Software-Defined Networking)
	물리적 환경의 데이터 라우팅에서 라우팅 관리를 인수하여 트래픽 라우팅을 제어
	애플리케이션 트래픽보다 영상 통화 트래픽을 우선적으로 처리하도록 시스템을 프로그래밍해서 모든 온라인 회의에서 일관된 통화 품질을 보장하도록 할 수 있음

네트워크 기능 가상화
- 데이터 가상화
- 애플리케이션 가상화
- 데스크톱 가상화

=>가상화 방식
- 호스트 운영체제 가상화
하드웨어 - 호스트 운영체제 - 가상화 소프트웨어 - 게스트 운영체제

호스트 운영체제나 게스트 운영체제에 제약 사항이 별로 없음

운영체제 위에 운영체제가 얹히는 방식이어서 오버헤드가 클 수 있음

- 하이퍼바이저 가상화
호스트 운영체제없이 하드웨어에 하이퍼바이저를 설치해서 사용하는 가상화 방식

오버헤드가 거의 없음

하드웨어와 운영체제 사이에서 물리적 시스템의 하드웨어에 직접 설치되는 경우를 베어메탈 하이퍼바이저라고 합니다.

서버 가상화 기술에서는 주류

- Container 가상화
호스트 운영체제 위에 Container 관리 소프트웨어를 설치하여 논리적으로 Container를 나누어서 사용

Container는 애플리케이션 동작을 위한 라이브러리와 애플리케이션 코드로 구성해서 각각 개별 서버처럼 사용 

오버헤드가 적어서 가볍고 빠른 장점이 있음

다양한 운영체제 사용이 안되고 보안적으로 완전히 격리되지 않음

컨테이너 가상화 소프트웨어
	OpenVZ
	LXC
	Linux VServer
	Docker
	Oracle Solaris Zones

- Container
운영체제가 아닌 의존성 요소만 포함된 애플리케이션

애플리케이션 인터페이스는 호스트 운영체제와 직접 연결되며 게스트 운영체제 같은 추가 레이어가 없기 때문에 성능은 향상되고 리소스도 낭비되지 않고 Image 파일 크기도 작음

호스트 운영체제 차원에서 격리하는데 Container 들이 의존성 요소를 공유하지 않음

장점
	하이퍼바이저와 게스트 운영체제가 없기 때문에 가벼움
	경량이기 때문에 만들어진 Image 복제, 이관, 배포가 쉬움
	게스트 운영체제를 부팅하지 않기 때문에 애플리케이션 시작 시간이 빠름
	가상 머신보다 경량이므로 더 많은 애플리케이션을 실행할 수 있음

- 애플리케이션 배포 방식이 변화
전통적 방식(운영체제에 애플리케이션 배포) -> 가상화 -> 컨테이너화

2)Docker
=>Container형 가상화 기술을 구현하기 위한 상주 애플리케이션 과 이 애플리케이션을 조작하기 위한 명령행 도구로 구성되는 애플리케이션
=>같이 사용되는 프로그램과 데이터를 격리시키는 기능을 제공하는 애플리케이션
=>특징
- 마이크로 서비스 전환은 물론 DevOps, Testing 등 다양한 분야에서 활용
- Linux Container 구현체의 de-facto

=>Docker는 Linux를 사용
- Linux가 필요
Windows 나 Mac에서도 Docker를 구동할 수 있지만 이 경우 내부적으로 Linux가 사용되며 Container에서 동작시킬 프로그램도 Linux용 프로그램
Docker가 Linux 운영체제에서 사용하는 것을 전제로 만들어졌기 때문

=>LXC(Linux Container)
- OS 수준의 가상화 구현: 단일 Linux 커널을 사용하는 제어 호스트에서 여러 개의 격리된 Linux System(Container) 실행
- 사용되는 기술
chroot: 특정 디렉토리를 최상위 디렉토리인 root 로 인식하게 설정하는 리눅스 명령
	유저 격리
	파일 격리
	네트워크 격리

cgroups: 자원을 제한하고 격리시키는 Linux 커널 기능

Namespace
	프로세스를 독립시켜주는 가상화 기술
	운영환경에 대한 애플리케이션 보기의 완전한 분리를 허용
	프로세스 트리, 네트워킹, 사용자 ID 및 마운트 된 파일 시스템 포함

=>데이터나 프로그램을 독립된 환경에 격리하는 이유
- 다른 프로그램과 특정한 디렉토리를 공유하거나 같은 경로에 있는 설정 정보를 사용하는 경우에 프로그램 하나를 업데이트하면 다른 프로그램에도 영향을 미치고 실행 환경이나 라이브러리, 디렉토리, 설정 파일에서 이런 현상이 나타날 수 있음

- 도커를 사용하면 이런 문제를 어느 정도 해결

=>Image 와 Container
- Image는 Container를 만드는 설계도(클래스) 역할을 수행하는 것이고 이미지를 가지고 동일한 Container(인스턴스)를 여러 개 생성할 수 있음
- 현재 컨테이너를 가지고 이미지를 생성하는 것도 가능
- Image를 이용해서 여러 도커엔진에서 동일한 모양의 컨테이너를 생성하는 것이 가능

=>Docker Hub
- Docker에서 제공하는 공식적인 Docker Image Registry
- 대부분의 경우는 Docker Hub에서 기본 이미지를 다운로드 받아서 레이어를 추가한 후 자신의 이미지를 생성해서 배포

=>다양한 형태로 조합이 가능한 Container 
- 하나의 애플리케이션으로 구성해도 되지만 여러 개의 애플리케이션을 묶어서 구성하는 것도 가능
- 워드프레스는 아파치 웹 서버 와 MySQL이 합쳐진 이미지

=>Docker Container는 일회용: 한 번 삭제되면 복구가 안됨

=>데이터 저장
- Container는 폐기하면 데이터도 소멸
- Docker가 설치된 물리적 서버의 디스크를 마운트해서 데이터를 저장하는 것이 가능

=>장점
- 애플리케이션 개발 및 운영을 Container 중심으로 할 수 있음
- 가상화 소프트웨어보다 가벼움
- 개발 환경 과 운영 환경을 거의 동등하게 재현 가능
- 물리적 환경의 차이나 서버 구성의 차이를 무시할 수 있음
- 클라우드 플랫폼 지원

=>추천하지 않는 경우
- Linux 운영체제의 동작이 필요한 경우
- 비 Linux 환경이 필요한 경우

=>Docker의 구성 요소
- docker client: 도커에 명령을 내릴 수 있는 CLI

- docker host: 도커를 설치한 서버 혹은 가상 머신

- docker swarm: 여러 docker 호스트들을 클러스터로 구성해서 관리할 수 있는 docker 오케스트레이션 도구

2)Docker Container Application 개발 흐름

애플리케이션 코드 개발 -> 베이스 이미지를 이용해서 Dockerfile 작성 -> Dockerfile을 빌드해서 새로운 이미지를 생성 -> 생성된 이미지를 이용해서 컨테이너를 생성해서 실행 -> 컨테이너 애플리케이션 테스트 -> 로컬 및 원격 저장소에 이미지를 저장(push) -> Git을 이용한 Dockerfile 관리 -> 동일한 환경에서 지속적 애플리케이션 개발을 수정해서 반복

컨테이너를 생성해서 실행할 때 여러 개의 컨테이너를 사용해야 하는 경우에는 docker-compose를 이용해서 다중 컨테이너로 실행하고 각각의 컨테이너를 테스트 한 후 애플리케이션 테스트로 넘어감

3)Docker 명령어 사용
=>모든 명령은 docker로 시작

=>기본 형식
docker 명령어 옵션 대상 인자

- penguin 이미지를 다운로드: docker image pull penguin
- penguin 이미지를 가지고 컨테이너를 생성: docker container run penguin
- penguin 이미지를 가지고 컨테이너를 생성: docker container start penguin
- penguin 이미지를 가지고 컨테이너를 생성하는데 백그라운드에서 실행: docker container run -d penguin

=>명령어는 상위 명령어와 하위 명령어 두 가지가 있는 상황에 따라서 상위 명령어는 생략해도 되는 경우가 있음

=>image 조작 관련 명령어
- pull:  다운로드로 image를 생략가능하고 옵션은 거의 사용하지 않음
- rm: 이미지를 삭제하는데 옵션은 거의 사용하지 않음
- ls: 내려받은 이미지 목록을 출력하는데 옵션을 거의 사용하지 않음
최근에는 docker images로 목록을 출력
- build: 도커 이미지를 생성하는 image를 생략가능하고 주요 옵션으로 t가 있는데 dockerfile의 이름이 다를 때 사용

=>container 관련 명령
- start: 컨테이너 시작하는데 container 생략 가능하고 주요 옵션은 i(대화식으로 실행)
- stop: 컨테이너 중지하는데 container 생략 가능하고 옵션 거의 사용 안함
- create: 컨테이너를 생성하는데 container 생략 가능하고 주요 옵션으로는 name, e, p, v 등
- run: 이미지가 없으면 내려받고 컨테이너를 생성하고 시작하는 것으로 container 생략 가능하고 주요 옵션으로는 name, e, p, v, d, i, t 등
- rm: 정지 상태의 컨테이너를 삭제하는데 container 생략 가능하고 주요 옵션으로는 f, v
- exec: 실행 중인 컨테이너 속에서 프로그램을 실행하는데 container 생략 가능하고 주요 옵션으로는 i, t
- ls: 컨테이너 목록을 출력하는데 주요 옵션으로 i가 있는데 최근에는 ps로 대신하는 경우가 많음
- cp: 도커 컨테이너와 호스트 컴퓨터간에 파일을 복사하는 명령으로 container 생략 가능하고 옵션은 거의 사용하지 않음
- commit: 도커 컨테이너를 이미지로 변환하는 명령으로 container 생략 가능하고 옵션은 거의 사용하지 않음

=>volume 조작을 위한 명령어
- create: 볼륨을 생성하는 명령어로 주요 옵션으로는 name
- inspect: 볼륨을 상세히 조회하는 명령
- ls: 볼륨의 목록을 출력하는데 주요 옵션으로는 a
- rm: 볼륨을 삭제
- prune: 사용되지 않는 볼륨을 삭제

=>network 조작을 위한 명령어
- create: 네트워크를 생성하는 명령어로 주요 옵션으로는 name
- inspect: 네트워크를 상세히 조회하는 명령
- ls: 네트워크 목록을 출력하는데 주요 옵션으로는 a
- rm: 네트워크를 삭제
- prune: 사용되지 않는 네트워크를 삭제
- connect: 컨테이너를 도커 네트워크에 연결

=>그 이외 명령어
- checkpoint: 현재 상태를 일시적으로 저장해서 나중에 해당 시점으로 되돌릴 수 있는 명령
- node: 도커 스웜의 노드를 관리하는 기능
- plugin: 플러그인을 관리하는 기능
- secret: 도커 스웜의 비밀값 정보를 관리하는 기능
- service: 도커 스웜의 서비스를 관리하는 기능
- stack: 도커 스웜에서 여러 개의 서비스를 합쳐 구성한 스택을 관리하는 기능
- swarm: 도커 스웜을 관리하는 기능
- system: 도커 엔진의 정보를 확인하는 기능
- login: 도커 레지스트리에 로그인
- logout: 도커 레지스트리에 로그아웃
- search: 도커 레지스트리 검색
- version, info: 도커 엔진 및 명령행 도구의 버전을 출력

3.도커 이미지
1)Docker Image
=>개요
- 컨테이너 형태로 소프트웨어를 배포하기 위해 필요한 모든 요소를 실행할 수 있는 포맷으로 컴파일 및 빌드한 패키지
- 독립적이기 때문에 의존성을 고려할 필요가 없음
- 특정 시점의 컨테이너 상태를 담은 스냅샷이라고도 함
- Docker 이미지를 이용해서 동일한 환경을 가진 여러 개의 컨테이너를 생성할 수 있음
- Docker 이미지는 여러 개의 구성되어 있음

=>이미지 검색
- docker search 명령을 이용하면 docker hub에 등록된 repository를 검색할 수 있음
- 형식
docker search [옵션] 검색_키워드

- 이미지를 검색하면 이미지이름 그리고 설명 과 star 수 그리고 공식 이미지 여부가 출력됩니다.
- 이름을 보면 docker hub의 네임스페이스는 library여서 이미지 이름은 library/이미지이름 형태인데 library/는 생략 가능
- 검색할 때는 보이지 않지만 이미지 뒤에는 :과 태그가 들어갑니다.
- 태그가 생략되면 latest
- 옵션으로 --limit 개수 를 이용해서 검색되는 이미지 개수를 제한하는 것이 가능합니다.

=>이미지 다운로드
- 명령
docker [image] pull [OPTIONS] name[:TAG | @IMAGE_DIGEST]
- 태그를 생략하면 latest 버전
- 태그는 일종의 버전

- jenkins/jenkins:lts 버전을 다운로드
docker pull jenkins/jenkins:lts

- debian 리눅스 최신 버전을 다운로드
docker pull debian:latest
docker pull debian

- 다운로드 받고 나면 앞의 경우는 namespace가 jenkins 이고 뒤의 경우는 생략되었는데 library 입니다.
jenkins/jenkins:lts는 jenkins 라는 저장소에 있는 jenkins:lts 이미지이고 
debian은 library라는 저장소에 있는 debian:latest 이미지 입니다.
앞에 네임스페이스를 생략하면 docker hub의 네임스페이스인 library가 자동으로 설정됩니다.

Digest는 분산 해시 값인데 절대로 중복될 수 없는 값인데 이미지는 여러 layer로 구성되어 있는데 이 layer 중에서 가장 핵심이 되는 정보를 바이너리 형태로 제공
이 값이 같으면 동일한 이미지로 간주

Status는 이미지가 로컬에 저장되었음을 나타내는 상태 표시

docker.io/library/debian:latest는 실제 이미지의 저장소 주소인데 docker.io는 도커 허브

- 옵션
a, all-tags: 저장소에 태그로 지정된 여러 image를 모두 다운로드

disable-content-trust: Image 검증 작업을 건너뛰는 것으로 기본값이 true

platform: 중요한 옵션인데 플랫폼을 지정하는 것으로 --platform=linux 형태로 설정
	가상 머신에 리눅스를 설치한 경우에는 가상 머신의 운영체제는 중요하지 않고 실제 물리적 컴퓨터가 어떤 것이냐에 따라 플랫폼이 달라집니다.
	MAC M 시리즈에서는 --platform linux/arm64를 붙여 주는 것이 좋습니다

q, quiet: 이미지를 다운로드 받을 때 상세한 출력을 숨김

- debian 리눅스 최신 버전을 다운로드: 아래 명령은 모두 동일한 명령
docker pull docker.io/library/debian:latest
docker pull library/debian:latest
docker pull debian:latest
docker pull debian

- 구글 레지스트리(gcr.io)를 이용하는 google-samples/hello-app:1.0 을 다운로드
docker pull gcr.io/google-samples/hello-app:1.0

=>이미지 목록 출력
- 명령: docker images 또는 docker image ls

- 내용
IMAGE                                 ID             DISK USAGE   CONTENT SIZE   EXTRA
debian:latest                         34cd9e9fd437        186MB         52.5MB

ID는 분산 해시의 앞 12 글자


=>이미지 상세 출력
- 명령: docker image inspect 이미지이름

=>이미지 다운로드 받아서 조회
- 다운로드 받을 이미지는 httpd 최신 버전 다운로드
docker pull httpd

- 이미지 상세 조회
docker image inspect httpd

- 생성 날짜 만 조회: [{Created: 값
docker image inspect --format="{{.Created}}" httpd

=>레이어 정보 확인
docker image history 이미지이름
- 어떤 명령들을 수행해서 이 이미지가 만들어졌는지 기반이 되는 베이스 이미지는 무엇인지 확인 가능

2)Docker 유니언 파일 시스템
=>도커를 이용해서 웹 서버를 구동
- httpd 이미지를 다운로드 받아서 컨테이너를 생성한 후 웹 페이지 코드를 컨테이너에 삽입하는 형태로 구동
- httpd 이미지는 Debian Linux에 apache web server를 설치한 구조

=>이미지는 불변의 읽기 전용 레이어들의 집합 구조인 유니언 파일 시스템
- 유니언 파일 시스템: 서로 다른 파일 시스템을 하나의 파일 시스템처럼 합쳐서 보여주는 기술
- 도커 이미지는 여러 개의 읽기 전용 레이어로 구성되고 그 위에 쓰기가 가능한 레이어를 한 장 추가해 주는 구조입니다.
- 도커를 가지고 컨테이너를 실행하면 기존의 레이어들은 읽기 전용으로 만들어지고 그 위에 읽고 쓰기가 가능한 레이어를 제공해서 변경된 정보는 그 레이어 위에 작성하도록 합니다.

=>도커의 모든 데이터 및 로그 정보 저장소는 /var/lib/docker
- 읽고 쓰기 레이어는 overlay2에 보관됩니다.
