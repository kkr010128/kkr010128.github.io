=>단위 테스트
- 개요
유닛 테스트는 컴퓨터 프로그래밍에서 소스 코드의 특정 모듈이 의도된 대로 정확이 동작하는지 검증하는 절차

모든 함수와 메서드에 대한 Test Case를 작성하는 절차로 이를 통해서 언제라도 코드 변경으로 인한 문제가 발생할 경우 단 시간 내에 파악하고 바로 잡을 수 있도록 해야 함

각 테스트 케이스는 서로 분리되어야 하고 이를 위해서 Mock Object(가짜 객체)를 생성하는 것도 좋은 방법 

유닛 테스트는 개발자 뿐만 아니라 보다 심도있는 테스트를 위해서 Tester에 의해 수행하기도 함

- 장점
문제점 발경이 쉬움
	프로그램을 작은 단위로 쪼개서 각 단위가 정확하게 동작하는지 검사하고 이를 통해 문제 발생 시 정확하게 어느 부분이 잘못되었는지를 재빨리 확인할 수 있기 때문에 프로그램의 안정성이 높아짐
	유닛 테스트는 개발 시간을 증가시키는 것 처럼 보이지만 개발 기간 중 대부분을 차지하는 디버깅 시간을 단축함으로서 여유로운 프로그래밍이 가능

변경이 쉬움
	리팩토링 후에도 해당 모듈이 의도대로 동작하고 있음을 유닛 테스트를 통해 확신할 수 있는데 이러한 테스트를 Regression Testing(회귀 테스트)이라 하며 어떻게 코드를 고치더라도 문제점을 금방 파악할 수 있고 수정된 코드가 정확하게 동작하는지 쉽게 알 수 있기 때문에 프로그래머들은 더 자주 코드를 변경할 수 있음
	지속적인 유닛 테스트 환경을 구축하면 어떠한 변화가 있더라고 코드와 그 실행이 의도대로 인지를 확인하고 검증할 수 있게 되며 확립된 개발 방법과 유닛 테스트의 범위에 따라서 프로그램의 정확성이 좌우됨

통합이 간단
	유닛 자체의 불확실성을 제거해주기 때문에 bottom-up(상향식) 테스트 방식에서 유용
	프로그램의 각 부분을 검사하고 그 부분들을 합쳐서 다시 검증하는 통합 테스트에서 더욱 더 빛을 발함

=>Code Coverage
- 개요
소프트웨어 테스트에서 사용되는 지표 중 하나로 코드의 실행 여부를 기반으로 코드의 품질과 완성도를 측정하는 방법

테스트 케이스를 실행할 때 코드 내의 각 요소가 실행되는 빈도를 측정하여 테스트 케이스가 커버하는 코드 비율을 나타내는 지표

코드 커버리지는 테스트 케이스의 실행 여부를 기준으로 계산하는데 이를 통해 테스트 케이스가 커버하지 않은 코드 블록을 실별하여 개발자가 이를 보완할 수 있도록 해줌

측정 요소
	Statement Coverage = 실행된 문장 수 / 전체 문장 수
	Branch Coverage = 실행된 조건 블록 수 / 전체 조건 블록 수
	Function Coverage = 실행된 함수 수 / 전체 함수 수
	Decision Coverage = 수행된 분기 수 / 전체 분기 수
	Condition Coverage = 수행된 조건 수 / 전체 조건 수

실제 작업에서는 특정 비율이 안되면 테스트 실패로 간주

- JaCoCo Code Coverage
설정
	build.gradle 파일의 plugins에 추가: id 'jacoco'

	build.gradle 파일에 Code Coverage 옵션을 설정

jacocoTestCoverageVerification{
    violationRules{
        rule{
            limit{
                minimum = 0.2 //20% 이상 테스트를 수행해야 한다는 의미
            }
        }
    }
}

실행
	./gradlew test jacocoTestCoverageVerification

	./gradlew test jacocoTestReport

보고서 확인
	build/reports/jacoco/test/html/index.html

보고서 내용
	Class
		클래스가 1번 이상 사용되었는지를 확인
		사용 기준은 메소드 중 1개 이상, 생성자, Static Initializer를 호출하면 사용된 것으로 간주
	
	Method
		메서드가 1번 이상 호출되었는지를 기준
		메서드 내부의 모든 코드가 실행되었는지는 판단 기준에서 제외

	Lines
		몇 개의 라인이 실행되었는지가 기준

	Branch 
		소스 코드 내 분기문에 대해 테스트의 실행 흐름이 어떻게 되는지 측정하는 것
		특정한 조건에 따라 코드 실행 흐름이 달라질 때 모든 분기문이 정상적으로 실행되는지 확인하는 것
		브랜치 커버리지가 100% 라면 라인 커버리지도 100% 이지만 라인 커버리지가 100%해서 Branch Coverage는 100%가 아닐 수 있음

	Instruction Coverage
		JaCoCo에서 제공하는 가장 작은 단위의 코드 커버리지
		자바 바이트 코드에서 실행되었거나 실행되지 않은 코드의 양에 대한 정보를 측정

	Complexisy by Type(Cxty - 코드의 복잡도)
		클래스나 인터페이스의 복잡도를 측정하는데 사용하는 순환 복잡도를 계산
		v(G) = B(the number of branches) - D(the number of decision points) + 1
			B는 코드가 갈수 있는 모든 흐름
			D는 조건문이나 루프문 과 같이 제어흐름을 결정하는 코드 구문을 의미

- 이점
버그 감소: 테스트 코드가 더 많은 부분을 실행하므로 버그를 사전에 검출하는데 도움이 되고 코드 커버리지가 낮으면 테스트 되지 않은 코드에서 버그가 발생할 수 있음

코드 품질 향상: 더 많은 코드가 테스트되고 버그가 감소하게 되므로 코드의 안정성과 신뢰성이 높아짐

유지보수 용이성

개발 생산성 향상

- 목표
코드 커버리지 100%가 무결점 소프트웨어를 의미하지는 않음

코드 커버리지가 100% 인데 문제가 있는 경우
	요구사항에 있는 기능 누락
	구현에 오류가 있는 경우
	테스트 케이스가 누락된 경우

단순하게 코드 커버리지를 높이기 위해서 테스트 케이스를 추가하는 것은 지양해야 하며 요구 사항 및 구현 코드에 대한 이해를 바탕으로 올바른 테스트 케이스를 생성해야 함

Google Testing Blog에 작성된 좋은 코드 커버리지는 코드의 비지니스 영향/중요도, 얼마나 자주 변경하는지, 코드의 복잡도, 유지 기간  및 도메인 변수에 따라 도메인 오너가 수준을 정하는 것이 좋다고 함
60% 정도이면 적절한 수준, 75% 정도이면 칭찬받을 만한 수준 그리고 90%를 모범적인 수준이라고 함

메서드 커버리지는 100%를 기본으로 하고 Instructions Coverage(Line Coverage)에 대한 지표를 도입하고 Branch Coverage를 더 향상시킬 수 있는 도전적인 목표를 수립하고 차근 차근 진행해 나가는 것을 권장

pipeline{
    agent any
    environment{
        SONAR_HOST_URL = "http://<SONARQUBE_HOST>:9000"
        SONAR_TOKEN = credentials('sonarqube-token')
    }
    stages{
        stage('github clone'){
            steps{
                git branch: 'main', url: 'https://github.com/<organization>/springunittest.git'
            }
        }
         stage('permission change'){
            steps{
                sh "chmod +x ./gradlew"
            }
        }

	    stage('compile'){
            steps{
                sh "./gradlew compileJava"
            }
        }

	    stage('unit test'){
            steps{
                sh "./gradlew test"
            }
        }
        stage("Sonarqube"){
            steps{
                withSonarQubeEnv('Sonarqube-Server'){
                    sh "./gradlew sonar -Dsonar.host.url=$SONAR_HOST_URL"
                }
            }
        }

    }
}
