13.DNS
1)개요
=>문자로 된 주소를 컴퓨터가 이해할 수 있는 IP 주소로 변환해주는 시스템
=>문자로 된 주소를 컴퓨터가 이해할 수 있는 IP 주소로 변환해주는 컴퓨터를 Name Server 또는 DNS Server 라고 하며 이 과정을 resolution 이라고 합니다.
=>문자로 된 주소를 이용하지 않고 IP 주소를 직접 사용하면 변환 과정이 생략되므로 인터넷 속도가 빨라질 수 있음

- Linux/Mac OS: /etc/hosts
- Windows: c:\Windows\System32\drivers\etc\hosts

3)DNS의 주요 구성 요소
=>DNS Recursive Resolver: 사용자로부터 쿼리를 받는 첫번째 지점으로 요청을 받아서 실제 주소를 찾음
=>Root NameServer: 호스트 이름을 IP 주소로 변환하는 첫번째 단계로 .com, .net 과 같은 TLB 서버의 위치를 알려줌
=>TLD Nameserver(최상위 네임 서버): .com, .org, .kr 등 도메인의 확장자를 관리하며 구체적인 도메인 정보를 가진 네임서버로 안내
=>Authoritative Nameserver: 실제 IP 주소가 저장된 최종 목적지로 갈 수 있도록 정확한 IP 주소를 알려줌

4)DNS 레코드 종류
=>A Record: 도메인을 IPv4 주소와 연결(가장 기본)
=>AAAA Record: 도메인을 IPv6 와 연결
=>CNAME: 한 도메인을 다른 도메인으로 연결
=>MX Record: 해당 도메인의 이메일을 수신할 메일 서버를 지정
=>TXT Record: 도메인에 대한 텍스트 정보를 담고 보안 인증에 사용

5)DNS Caching
=>매번 동일한 조회 과정을 거치면 속도가 느려지기 때문에 한 번 찾은 주소는 일정 기간 저장
=>다음에 접속할 때는 DNS Server에 문의하지 않고 컴퓨터 내부에 저장된 기록(브라우저/OS 캐싱)을 가지고 접속
=>TTL(Time To Live): DNS 레코드가 캐시에 저장되는 유효 기간

6)DNS 서버 설정
=>설정 방법
- /etc/netplan 디렉토리의 yaml 파일
- /etc/resolv.conf 파일

=>IP 주소를 찾아가는 흐름
URL 입력 ->/etc/host.conf 조회 -> /etc/hosts(있으면 IP 주소를 획득해서 접속) -> 없으면 /etc/resolv.conf ->네임서버 설정이 존재하면 네임서버에게 질의하고 응답을 받는데 네임서버 설정이 없으면 호스트 이름을 알 수 없다고 에러를 발생

7)도메인 이름 체계
=>트리 구조
=>ROOT Name Server는 com, net, org, edu 등의 네임서버 와 국가 도메인인 kr, fr, uk, sp 등을 관리하는 네임서버
=>com Name Server가 다시 naver, google 등 2단계 도메인을 관리하는 네임 서버

16.File Sharing
1)FTP
=>개요
- File Transfer Protocol은 네트워크를 통해 컴퓨터간에 파일을 전송하기 위한 가장 기본적인 표준 통신 규약
- 다른 프로토콜 과 달리 2개의 포트를 동시에 사용

=>핵심 작동 원리: 2개의 채널
- Control Channel(21): 사용자의 아이디 비밀번호 확인 및 명령어를 전달
- Data Channel(20): 실제 데이터가 오가는 통로로 제어 채널에서 명령이 전달되면 실제 파일 전송이 이루어 짐

=>접속 방식
- 능동 모드(Active): 서버가 클라이언트에게 접속을 시도하는 방식
- 수동 모드(Passive): 클라이언트가 서버에게 접속을 시도하는 방식, 대부분의 웹 브라우저나 공유기가 사용하는 방식

=>종류
- 기본 FTP: 아이디와 비밀번호가 암호화되지 않은 채로 전송되는 방식인데 해킹에 취약
- SFTP(Secure FTP): SSH 기술을 이용해서 전송 과정 전체를 암호화하는 방식으로 현재 가장 많이 사용되는 방식
- FTPS(FTP over SSL/TLS): 웹 사이트 주소 앞에 https를 붙이는 것처럼 SSL 인증서를 사용하여 암호화하는 방식

=>장점: 대용량 파일을 일괄 전송하기에 매우 효율적이고 전송 속도가 빠름
=>단점: 보안 설정을 하지 않으면 정보 유출 위험이 크고 설정이 복잡해질 수 있음

3)SSH를 이용한 파일 전송

=>SCP(Secure Copy): 가장 빠르고 간단하게 파일을 복사할 때 사용하는데 명령어 한 줄로 전송이 끝나는 방식

scp [계정]@[IP주소]:[파일경로] [로컬경로]

=>pem 파일을 이용한 인증
- pem 파일을 생성: ssh-keygen -t rsa -b 4096 -m PEM -f 파일경로
- 파일 소유자에게만 읽기 권한 부여: chmod 400 파일경로

- 로컬에서 원격지로 파일 보내기
scp -i pem파일경로 [파일 경로] [계정]@[IP주소]:[저장경로]

- 원격지에서 로컬로 파일 보내기
scp -i pem파일경로 [계정]@[IP주소]:[파일경로] [로컬경로]

4)NFS
=>개요
- NFS(Network File System)는 네트워크 상의 다른 컴퓨터의 파일 시스템을 마치 자신의 로컬 디스크에 있는 것 처럼 사용할 수 있게 해주는 클라이언트/서버 프로토콜
- 현재는 유닉스 와 리눅스 환경에서 표준 파일 공유 프로토콜로 사용됨

=>주요 특징
- Transparency(투명성): 사용자는 파일이 원격 서버에 있는지 로컬 디스크에 있는지 구분하지 않고 동일한 명령어로 파일을 읽고 쓸 수 있음
- 중앙 집중 관리: 데이터를 서버 한 곳에 모아 관리하므로 백업이나 보안 정책 적용이 효율적
- 플랫폼 독립성: RPC(Remote Procedure Call - 원격 프로시저 호출, 다른 컴퓨터의 메서드를 호출) 메커니즘을 사용하여 서로 다른 운영체제 간에도 파일 공유가 가능

=>장점
- 비용 절감
- 편의성: 사용자 홈 디렉토리를 NFS로 설정하면 어떤 컴퓨터에서 로그인 하든 동일한 작업 환경을 유지할 수 있음

=>단점
- 네트워크 의존성
- 보안이 취약: 초창기 버전은 호스트 IP 기반의 인증 방식을 주로 사용해서 보안에 취약할 수 가 있음

=>활용 사례
- 클러스터 서버: 여러 대의 웹 서버나 애플리케이션 서버가 동일한 데이터를 공유해야 할 때 사용
- 데이터 백업: 여러 호스트의 데이터를 중앙 스토리지 서버로 모으는 용도로 활용
- kubernetes: 컨테이너 환경에서 영구 볼륨(Persistent Volume)으로 NFS를 연결해서 데이터의 휘발성을 방지
