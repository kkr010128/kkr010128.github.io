7)playbook
=> 설정과 함께 nginx를 배포
- nginx가 실행되면 보여질 welcome file 작성: index.hml
<html>
  <head>
    <title>Welcome To Nginx</title>
  </head>
  <body>
    <h1>nginx configured by ansible</h1>
  </body>
</html>

- nginx 설정 파일: nginx.conf
server {
  listen 80 default_server;
  listen [::]:80 default_server ipv6only=on;

  root /usr/share/nginx/html;
  index index.html index.htm;

  server_name localhost;

  location / {
    try_files $uri $uri/ =404;
  }
}

- 배포파일: webservers.yml
- name: Configure WebServer with nginx 
  hosts: all
  become: yes     #관리자 권한으로 명령을 수행
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present

    - name: Copy nginx config file
      copy:
        src: nginx.conf
        dest: /etc/nginx/sites-available/default

    - name: Manage Configuration
      file: >
        dest=/etc/nginx/sites-enabled/default
        src=/etc/nginx/sites-available/default
        state=link
    - name: Copy Welcome File
      copy:
        src: index.html
        dest: /usr/share/nginx/html/index.html
    - name: Restart Nginx
      service: name=nginx state=restarted

- 실행: ansible-playbook -b -K webservers.yml

- 확인: curl 관리노드의IP

- nginx를 제거하는 배포파일: remove-nginx.yml
- name: Remove with nginx
  hosts: all
  become: yes     #관리자 권한으로 명령을 수행
  tasks:
    - name: Stop Nginx Service
      service:
        name: nginx
        state: stopped
      ignore_errors: yes
    - name: Remove Nginx and related packages
      apt:
        name:
          - nginx
          - nginx-common
          - nginx-full
          - nginx-core
        state: absent
        purge: yes
        autoremove: yes
    - name: Reload Systemd daemon
      systemd:
        daemon_reload: yes

=>반복문
- 반복문을 사용하지 않는 구조
- hosts: all
  tasks:
    - name: Check sshd state
      ansible.builtin.service:
        name: ssh
        state: started
      become: yes
    - name: Check rsyslog state
      ansible.builtin.service:
        name: rsyslog
        state: started
      become: yes

- 반복문 사용
- hosts: all
  tasks:
    - name: Check sshd and rsyslog state
      ansible.builtin.service:
        name: "{{ item }}"
        state: started
      become: yes
      loop:
        - ssh
        - rsyslog

- 변수에 저장해서 수행
- hosts: all
  vars:
    services:
      - ssh
      - rsyslog
  tasks:
    - name: Check sshd and rsyslog state
      ansible.builtin.service:
        name: "{{ item }}"
        state: started
      become: yes
      loop: "{{ services }}"

=>작업 실패 무시
- 개요
앤서블은 플레이 시  각 작업의 반환 코드를 평가하여 작업의 성공 여부를 판단
작업이 실패하면 이후의 모든 작업을 건너뜀
작업이 실패해도 플레이를 계속 실행할 수 있도록 할 수 있는데 이 때 사용하는 키워드가 ignore_errors

- 에러가 발생해도 다음 작업을 수행하기
- hosts: all
  tasks:
    - name: Install apache3
      ansible.builtin.dnf:
        name: apache3
        state: latest
      ignore_errors: yes
    - name: Print msg
      ansible.builtin.debug:
        msg: "Before task is error"

- 에러가 발생한 경우 핸들러 호출
force_handlers: yes로 설정하면 작업이 실패해서 플레이가 중단되어도 알림을 받은 핸들러가 호출

10)Role
=>개요
- 플레이북을 재사용을 하기 위한 개념
- 사용하는 이유
콘텐츠를 그룹화해서 코드를 다른 사용자와 쉽게 공유
웹 서버, 데이터베이스 서버 또는 Git Repository 와 같은 시스템 유형의 필수 요소를 정의할 수 있음
대규모 프로젝트를 쉽게 관리할 수 있음
다른 사용자와 동시에 개발할 수 있음
잘 작성한 롤은 앤서블 갤럭시를 이용해서 공유하거나 다른 개발자가 만든 롤을 가져올 수 도 있음 

=>구조
- 최상위는 롤의 이름
- 하위 구조
defaults: main.yml 파일에는 롤이 사용될 때 덮어쓸 수 있는 롤 변수의 기본값이 포함되어 있는데 이는 우선 순위가 낮고 플레이북에서 변경

files: 롤 작업에서 참조하는 정적 파일

handlers: main.yml 파일에는 롤의 핸들러 정의를 포함

tasks: 롤의 작업 정의를 포함

templates: Jinja2 템플릿 포함

tests: 롤을 테스트하는데 사용할 수 있는 인벤토리와 test.yml 플레이북을 포함

vars: 롤의 변수 값을 정의

- 개요

11)도커 설치
=>도커 설치를 위한 playbook
- hosts: all
  become: yes
  tasks:
    - name: GPG키 디렉토리 생성
      ansible.builtin.file:
        path: /etc/apt/keyrings
        state: directory
        mode: '0755'
    - name: GPG 키 다운로드
      ansible.builtin.get_url:
        url: https://download.docker.com/linux/ubuntu/gpg
        dest: /etc/apt/keyrings/docker.asc
        mode: '0644'
        force: yes
    - name: 저장소 강제 주입
      ansible.builtin.copy:
        dest: /etc/apt/sources.list.d/docker.list
        content: "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu noble stable"
        mode: '0644'
    - name: 패키지 목록을 강제로 업데이트
      ansible.builtin.apt:
        update_cache: yes
    - name: 도커엔진 설치
      ansible.builtin.apt:
        name:
          - docker-ce
          - docker-ce-li
          - containerd.io
        state: present
        update_cache: yes
    - name: 도커 서비스 시작
      ansible.builtin.service:
        name: docker
        state: started
        enabled: yes
