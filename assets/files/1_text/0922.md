3)Ansible
=>개요
- 여러 개의 서버를 효율적으로 관리할 수 있게 해주는 파이썬으로 만들어진 환경 구성 자동화 도구
- IT Infrastructur 자동화 도구
- 모든 호스트에 대해 병렬로 작업을 수행
- 다음 작업으로 넘어가기 전에 모든 호스트에서 작업이 완료될 때 까지 대기
- 작업은 지정한 순서대로 진행

=>장점
- Agentless
SSH로 접속해서 작업을 수행
- Idempotency(멱등성): 동일한 연산을 여러 번 적용하더라도 결과가 달라지지 않는 성질
- Simple
YAML 형식과  Jinja2 템플릿을 사용
다양한 플레이북 예제를 제공
- Push 기반 서비스

=>수행 가능한 작업
- 소프트웨어 설치
- 파일 및 스크립트 배포
- 다운로드
- 스크립트 실행
- 버전 컨트롤
- 암호화
- 인프라 스트럭쳐: Public Cloud, VMWare, OPenStack 등
- Container
- Build & Test
- 운영체제 관련 명령

=>결과
- ok
- failed
- changed
- unreachable

=>사용 가능 환경
- 리눅스 와 유닉스 그리고 Mac OS에서 사용 가능하고 Windows에서는 WSL을 지원하는 환경
- 앤서블 코어가 설치되고 플레이북을 작성하여 실행하는 제어노드와 작업이 수행되는 관리노드로 구성됨
- 앤서블은 제어 노드에만 설치되고 관리 노드에는 설치되지 않음

=>관련 자료
- 공식 git hub: https://github.com/ansible
- 공식 문저: https://docs.ansible.com/ansible/latest/index.html

=>Inventory
- 제어 노드가 제어하는 관리 노드의 목록을 나열한 파일
- IP 나 도메인을 나열하는데 그룹화가 가능

=>모듈
- 앤서블은 관리 노드의 작업을 수행할 때 SSH를 통해 연결한 후 앤서블 모듈 rules라는 스크립트를 푸시해서 작동
- 대부분은 모듈은 원하는 시스템 상태를 설명하는 매개변수를 허용하고 모듈 실행이 완료되면 제거됨

=>플레이북
- 관리 노드에서 수행할 작업들을 YAML 문법을 이용해서 순서대로 작성한 파일

4)Ubuntu에 설치: 제어 노드에 설치
=>sudo apt update
=>sudo add-apt-repository --yes --update ppa:ansible/ansible
=>sudo apt install -y ansible
=>확인: ansible --version
=>동작 확인: ansible localhost -m ping

=>접속 설정
- 제어 노드와 관리 노드에는 python 이 설치되어 있어야 합니다.
- 제어 노드에서 관리 노드로 SSH 접속이 가능한지 확인

=>새로운 유저를 생성해서 접속 가능하도록 설정
- 신규 유저 생성: sudo adduser 유저이름
- 비밀번호 설정: sudo passwd 유저이름
- 유저 권한 설정
sudo chmod u+w /etc/sudoers
sudo vi /etc/sudoers 로 편집기로 열어서 유저이름 ALL=(ALL:ALL) NOPASSWD:ALL
- SSH 재실행: sudo service ssh restart

=>비밀번호 없이 접속
- 접속하고자 하는 컴퓨터에서 ssh-keygen 명령 실행
- ssh-copy-id 계정@접속하려는 컴퓨터 IP 나 도메인

6)기본 명령어
=>실행 옵션
-i : 적용될 호스트들에 대한 파일 경로로 생략하면 /etc/ansible/hosts 파일
-m: 사용할 모듈 선택
-k: 관리자 암호 요청
-K: 관리자 권한 상승 - sudo가 붙는 명령 실행시 사용 
--list-hosts: 적용되는 호스트 목록

=>ansible은 동일한 명령을 여러 번 수행하면 한 번만 수행

=>ansible 모듈 목록: https://docs.ansible.com/ansible/2.9/modules/list_of_all_modules.html#

=> Shell 명령어 수행: ansible all -m shell -a "free -h"

=>파일 
touch test.txt

ansible all -m copy -a "src=./test.txt dest=/tmp"

=>nginx를 설치 및 삭제
- 어떤 계정으로 ssh 접속을 하는지 알고자하는 경우에는 ansible all -m shell -a "whoami"
- ubuntu 설치와 삭제에 관련된 모듈은 apt
옵션으로 name에 패키지 이름을 state에 상태를 설정하면 됩니다.
state에 present를 설정하면 설치가 이루어지고 absent를 설정하면 삭제가 됩니다.
- -b 옵션을 설정하면 권한이 상승하게 되는데 sudo 명령을 사용할 때 이용
- -K를 추가하면 접속한 계정의 비밀번호를 물어보게 됩니다.

- nginx 설치
ansible all -m apt -a "name=nginx state=present" -b -K

- nginx 삭제
ansible all -m apt -a "name=nginx state=absent purge=yes autoremove=yes" -b -K

7)playbook
=>개요
- 서버가 가져야 할 상태를 정의한 설계도
- 여러 단계의 복잡한 작업을 순서대로 기록해놓은 스크립트
- YAML 형식
- 동일한 playbook을 여러 번 실행해도 이미 설정이 완료된 상태라면 시스템에 중복으로 변경을 가하지 않음
- 선언적 구조: 무엇을 어떻게 설치하라는 절차보다 결과적으로 어떤 상태가 되어야 하는지를 기술

=>playbook의 기본 구조
- play: 어떤 대상에게 작업을 할 것인지 정의
- task: 실제로 실행할 구체적인 작업 단위
- module: task가 실행하는 도구
- handler: 특정 조건이 충족되었을 때 실행되는 보조 작업

=>작성과 실행
- ping-test.yml 파일을 생성하고 작성

    - name: ping

- 실행 명령어: ansible-playbook ./ping-test.yml

=>디렉토리 생성(file 모듈을 이용하는데 path에 경로를 state에 파일인지 디렉토리인지를 mode에 권한을 설정) 및 파일 다운로드(get_url 모듈을 이용해서 url 과 dest를 설정하면 됩니다.)
- name: Download Tomcat
  hosts: all
  tasks:
    - name: Create a Directory
      file:
        path: ~/tomcat9
        state: directory
        mode: 0755
    - name: Download Tomcat9
      get_url:
        url: https://archive.apache.org/dist/tomcat/tomcat-9/v9.0.8/bin/apache-tomcat-9.0.8.tar.gz.sha512
        dest: ~/tomcat9

- 동작 확인 방법
shell 모듈 이용:  쉘 환경에서 복잡한 명령을 실행할 때 사용하는 것으로 파이프라인, 리디렉션, 환경 변수 설정 등이 필요할 때 유용하기는 하지만 보안상 쉘 인젝션 유의

ansible all -m shell -a "systemctl status nginx"

command 모듈 이용: 단순한 시스템 명령을 안전하게 실행할 때 사용하는데 쉘 기능을 지원하지 않기 때문에 보안성이 높음

ansible all -m command -a "nginx -v"

nginx는 웹 서버이므로 "curl 컴퓨터의IP" 명령을 이용해서 확인 가능

- nginx 제거
- name: nginx 
  hosts: all
  become: yes     #관리자 권한으로 명령을 수행
  tasks:
    - name: Stop Nginx
      service:
        name: nginx
        state: stoopped
      ignore_error: yes #nginx가 없어서 에러가 발생해도 다음 작업을 진행하도록 설정
    - name: Remove Nginx
      apt:
        name:
          - nginx
          - nginx-common
          - nginx-full
          - nginx-core
        state: absent
        purge: yes		#설정 파일까지 삭제
        autoremove: yes   #사용하지 않는 의존성 패키지 같이 삭제
    - name: Reload systemd daemon
      systemd:
        daemon_reload: yes

- 제거 확인 방법
ansible all -m shell -a "systemctl status nginx"

=> 설정과 함께 nginx를 배포
- nginx가 실행되면 보여질 welcome file 작성: index.hml
<html>
  <head>
    <title>Welcome To Nginx</title>
  </head>
  <body>
    <h1>nginx configured by ansible</h1>
  </body>
</html>

- nginx 설정 파일: nginx.conf
server {
  listen 80 default_server;
  listen [::]:80 default_server ipv6only=on;

  root /usr/share/nginx/html;
  index index.html index.htm;

  server_name localhost;

  location / {
    try_files $uri $uri/ =404;
  }
}

- 배포파일: webservers.yml
- name: Configure WebServer with nginx 
  hosts: all
  become: yes     #관리자 권한으로 명령을 수행
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present

    - name: Copy nginx config file
      copy:
        src: nginx.conf
        dest: /etc/nginx/sites-available/default

    - name: Manage Configuration
      file: >
        dest=/etc/nginx/sites-enabled/default
        src=/etc/nginx/sites-available/default
        state=link
    - name: Copy Welcome File
      copy:
        src: index.html
        dest: /usr/share/nginx/html/index.html
    - name: Restart Nginx
      service: name=nginx state=restarted
