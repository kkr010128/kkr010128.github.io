9.Packaging
1)kustomize
=>개요
- 쿠버네티스 매니페스트 관리 도구로 매니페스트의 구성 관리를 구현
- kustomize의 기본인 매니페스트 생성 기능은 kubectl도 제공
- base 매니페스트의 변경 위치를 정의한 패치 매니페스트를 준비하고 병합된 매니페스트를 출력

=>제공하는 기능
- 여러 매니페스트 파일을 하나의 매니페스트로 병합
- 레이블 등 공통 부분을 설정하여 매니페스트 파일의 중복 감소
- 오버레이의 재사용성을 통해 복수의 환경 구성 관리가 용이
- 시크릿 생성

=>설치
- kubectl에도 kustomize가 있지만 kustomize의 다양한 기능을 이용하고자 할 때는 별도로 설치

여러 언어와 도구의 버전을 한 곳에서 관리할 수 있는 통합 버전 관리자

- 매니페스트 정리
kustomization.yaml 파일을 생성해서 매니페스트 파일을 결합하는 것이 kustomize의 기본 기능

kustomize create --autodetect 명령을 사용하면 현재 디렉토리 내의 매니페스트 파일을 정리하기 위한 kustomization.yaml 파일을 생성할 수 있음

kustomization.yaml 파일의 내용

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
- deployment.yaml
- ingress.yaml
- service.yaml
	
resources 항목에 구성 관리의 대상이 되는 매니페스트 파일이 상대 경로로 나오게 됨

정리를 한 결과를 출력하고자 할 때는 kustomize build .

배포: kustomize build . | kubectl apply -k .

삭제: kustomize build . | kubectl delete -k .

2)Helm
=>개요
- CNCF가 관리하는 쿠버네티스 패키지 관리 도구
- 오픈 소스
- Helm > Chart > Manifest

=>Helm, Chart, Manifest의 관계
- 여러 매니페스트 파일의 템플릿을 정리할 수 있는데 대규모 애플리케이션이라면 매니페스트 템플릿도 많아지고 관리도 복잡하기 때문에 Chart로 분할해서 관리
- Chart는 다른 Chart와 의존 관계를 가질 수 있음
- 서드 파티의 Helm 차트 리포지토리에서 다운로드 가능
- Helm 의 Chart를 관리하고 Chart를 이용해서 매니페스트를 관리

=>PV 와 PVC를 생성해서 mariadb에 연결해서 설치
- PV 와 PVC 생성
디렉토리 생성: sudo mkdir -p /data/mariadb

소유자 변경: sudo chown -R 1001:1001 /data/mariadb

권한 변경: sudo chmod 777 /data/mariadb

PV 매니페스트 생성: mariadb-pv.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: mariadb-hostpath-pv
  labels:
    type: local
spec:
  storageClassName: manual
  capacity:
    storage: 1Gi
  accessModes:
    - ReadWriteOnce
  hostPath:
    path: /data/mariadb
    type: DirectoryOrCreate
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mariadb-pvc
spec:
  storageClassName: manual
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi

PV 배포: kubectl apply -f mariadb-pv.yaml

mariadb values 설정을 위한 values 파일: mariadb-values.yaml
auth:
  rootPassword: "SecretRootPassword123!"
  database: "testdb"
  username: "dbuser"
  password: "UserPassword123!"

primary:
  persistence:
    enabled: true
    existingClaim: "mariadb-pvc"

architecture: standalone

배포: helm install my-mariadb bitnami/mariadb -f mariadb-values.yaml

=>helm을 직접 생성

type: application

- 값을 채우는 values.yaml

  repository: mariadb
  tag: "11.4"
  pullPolicy: IfNotPresent

  database: "appdb"
  user: "appuser"
  password: "UserPassword123!"

  storageSize: "1Gi"

- secret 파일: template/secret.yaml

  mariadb-password: {{ .Values.mariadb.password | quote }}
