2.Jenkins
1)Jenkins
=>개요
- 자바로 작성된 오픈 소스 자동화 서버
- Apache Tomcat 처럼 servlet container 내부에서 실행되는 서버 시스템
- 방대한 플러그인 덕분에 지속적 통합 및 지속적 인도 프로세스를 구축하는데 많이 사용하는 도구

=>특징
- 다양한 프로그래밍 언어를 지원
- 다양한 빌드 도구 지원
- 이식성: 거의 모든 운영체제에서 실행 가능
- 대부분의 버전 관리 시스템을 지원: Git, SVN 등
- 분산 처리 지원
- 단순성
- 코드 방식 지원

=>CI/CD 프로세스
- 여러 명의 개발자가 자신의 브랜치에서 변경을 수행하고 중앙 레포지토리에 푸시하고 코드 리뷰가 끝나면 메인 브랜치에 병합
- 메인 브랜치가 변경되었음을 젠킨스에 통보를 하거나 젠킨스가 인지
- 젠킨스가 인지를 하면 작업을 시작

=>젠킨스의 작업
- 소스 코드 관리 시스템에 맞는 플러그인을 통해 레포지토리에서 변경된 파일을 가져옴
- Maven 같은 빌드 도구 와 젠킨스 플러그인을 이용해서 컴파일
- 빌드 도구를 재사용해서 컴파일 된 코드의 단위/통합 테스트를 실행
- 정적 분석 도구를 실행해서 코딩 표준을 준수하는지와 데드 코드가 있는지를 확인
- 실행 가능한 파일로 번들링: java의 경우 jar 나 war로 생성 - 최근에는 이 파일을 Docker Image로 많이 만듬
- 빌드된 라이브러리 파일을 프로덕션 환경으로 배포: 이 영역은 다른 배포 도구를 사용하기도 함
- 배포된 애플리케이션을 테스트 할 수 있는 자동화 도구(Web 의 경우 Selenium)를 사용해서 배포된 애플리케이션을 테스트
- 수행 결과를 이메일이나 슬랙 같은 곳에 전송

=>Architecture
- Master & Agent 방식
트리거나 알림은 Master의 역할
Master가 각 Agent에게 작업을 할당해서 실행

- 확장성
수직적 확장
	마스터의 성능을 높이는 방식
	유지보수 측면에서 효율적
	모든 업그레이드나 스트립트, 보안 설정 등을 한 곳에서만 하면 됨

수평적 확장
	인스턴스를 늘려나가는 방식
	단점
		프로젝트 간의 통합 자동화가 어려움
		유지보수 하는 시간이 늘어남
	장점
		마스터 역할을 수행하는 컴퓨터의 하드웨어가 고사양일 필요가 없음
		마스터 각각을 다르게 설정하는 것이 가능
		마스터 인스턴스 하나에 장애가 발생해서 다른 마스터로 작업을 계속 수행
		인프라를 표준 인프라와 필수 인프라로 구분해서 작업하는 것도 가능

- 테스트 용 과 프로덕션 용을 구분해서 사용
넷플릭스가 처음 도임
넷플릭스에서는 하루에 2천 개의 빌드를 수행하는 것이 가능
인프라의 일부는 aws에서 일부는 온프레미스에서 구축

4)Jenkins의 작업
=>Jenkins 프로젝트의 구성
- 작업을 수행하는 시점(Trigger): 어넺 시작할 지 지시
- 작업을 구성하는 단계별 태스크(빌드 스텝): 특정 목표를 수행하기 위해서 태스크를 step 별로 구성할 수 있는데 이를 Build Step 이라고 합니다.
- 태스크가 완료 후 수행할 명령(Post-Build Action): 태스크 실행이 끝나고 Jenkins 수행할 작업

=>Jenkins Build
- Jenkins 작업의 특정 실행 버전
- 빌드를 수행하면 고유한 빌드 번호가 부여되고 이 번호로 작업 실행 중에 생성된 아티팩트 및 로그 등이 저장됨

=>작업 종류
- Pipeline Job

- Freestyle: 일반적인 형태의 빌드 작업인데 테스트 실행, 빌드 및 패키징 그리고 보고서 전송 같은 간단한 작업을 할 수 있음

5)Free Style Job 생성하고 빌드
=>작업 생성
- 대시보드에 접속해서 New Item을 클릭하고 Free Style Job을 선택하고 이름을 입력
- Description: 작업의 설명이나 목적을 입력
- GitHub project: GitHub 연결, GitHub Plugin을 설치해야 사용 가능

- Throttle builds: 동시에 실행될 빌드 수를 제한, 서버 리소스 과부하를 방지하기 위해서 빌드의 수를 제한 
Throttle Concurrent Builds Plugin을 설치해야 사용 가능

오래된 빌드 삭제: 제한 값을 초과하면 오래된 빌드를 삭제

이 빌드는 매개변수가 있습니다: 프로젝트를 빌드할 때 외부에서 매개변수를 대입받을 수 있는 프로젝트

필요한 경우 concurrent 빌드 실행: 동시에 빌드를 수행해서 작업 시간을 단축시키고자 할 때 사용하는 옵션으로 하드웨어 성능이 좋아야 함

- Quiet period
대기 시간을 설정

설정하면 새로운 빌드가 즉시 시작되지 않음

빌드 큐에 추가가되고 지정된 시간이 지난 다음에 빌드 시작

여러 개의 코드 커밋을 모아서 수행할 때 유용한 기능
여러 개발자가 코드 레포지토리로 거의 동시에 커밋을 하게 되면 첫번째 커밋이 이루어지는 즉시 빌드가 수행되서 나머지 커밋은 이 빌드에 반영되지 않을 수 있으므로 설정

초 단위로 설정

- 재시도 횟수
옵션을 설정하지 않은 상태에서 SCM(소스 코드 관리 도구) 시스템을 사용하도록 작업을 구성하면 첫번째 체크아웃 시도가 실패하자 마자 바로 작업 실패로 처리

설정을 해서 체크아웃이 바로 되지 않는 경우 재시도를 하도록 해주어야 합니다.

재시도 간격은 기본적으로 10초입니다.


- 업스트림 프로젝트가 빌드하는 동안 빌드 멈춤
하나의 작업에서 생성된 아티팩트가 다른 작업에 사용되도록 2개의 작업을 구성할 수 있음
하나의 작업을 다른 작업에 종속되게 구성하는 것
1번 프로젝트가 도커 이미지를 만드는 작업이고 2번 프로젝트가 도커 이미지를 쿠버네티스 클러스터에 배포되는 작업이라고 하면 1번 프로젝트가 종료되고 2번 프로젝트라 진행되어야 합니다.
이 때 1번 프로젝트를 2번 프로젝트의 upstream job이 되고 2번은 1번 프로젝트의 downstream job

	Delete workspace before build starts: 빌드 실행 전에 workspace를 완전히 삭제해서 이전 빌드에서 남은 파일이나 캐시가 새 빌드에 영향을 주지 않도록 하는 것

	Use secret text(s) or file(s): 민감한 값(비밀번호, 토큰 등)을 빌드 환경에 안전하게 주입하기 위한 기능
					    Credentials Binding Plugin을 설치해야 사용할 수 있음

	Add timestamps to the Console Output: 빌드 로그 줄 앞에 시간 정보가 표시되어 디버깅이나 성능 분석 시 매우 유용

	Inspect build log for published build scans: Gradle 이나 Maven 같은 빌드 도구를 사용할 때 Build Scan 기능을 활성화한 경우 빌드 로그에서 Build Scan URL을 확인할 수 있도록 해주는 기능

	Terminate a build if it's stuck: 일정 시간이상 빌드를 수행하는 경우 강제 종료 시키는 기능, 리소스 낭비나 빌드 대기열 문제를 해결하기 위해서 사용

	With Ant: Java 프로젝트를 빌드할 때 사용하는 옵션인데 이 기능을 사용할려면 Jenkins에 Ant를 설정하고 이 후 Job에서 Invoke Ant 떠는 withAnt 스텝을 사용
	
	Ant(Apache Ant)는 자바 프로젝트를 빌드하고 자동화하는 도구
	컴파일하고 테스트하고 JAR/WAR로 묶고 배포까지 할 수 있는 도구
	Ant -> Maven -> Gradle 로 발전한 상태라서 최근에는 Ant로 빌드를 하는 경우가 극히 드뭅니다.
