=>ping
- 외부와 통신이 되는지 확인하거나 외부 서버가 동작 중인지 확인할 때 사용
- 형식: ping [옵션] [목적지 주소]
- 옵션
a: 통신이 되면 소리가 남
q: 테스트 결과를 지속적으로 보여주지 않고 종합 결과만 출력
c 개수: 보낼 패킷 수를 지정

64 bytes from server (192.168.0.101): icmp_seq=1 ttl=64 time=1.52 ms: 패킷의 크기가 64바이트 이고  icmp_seq는 응답이 보낸 패킷의 순서이고 ttl은 Time To Live의 약자로 패킷이 목적지에 도달하기까지 거친 라우터 수를 간접적으로 알려주는데 128 이나 64부터 시작을하고 라우터를 거칠 때 마다 1씩 감소하므로 높을 수로 목적지까지의 경로가 짧거나 안정적이며 time은 왕복 시간

5 packets transmitted, 5 received, 0% packet loss, time 4005ms
rtt min/avg/max/mdev = 1.066/2.377/5.184/1.487 ms
5개의 패킷을 전송해서 5개의 패킷을 받았으므로 읽어버린게 없고 모든 패킷을 전송하고 응답받는데 4005ms를 사용했고 최소/평균/최대/표준편차 입니다.

- 통신이 안될 때는 ping 명령으로 gateway를 확인하고 DNS를 확인

- 형식: netstat [옵션]
- 옵션

- 열려있는 포트를 사용 중인 프로세스 확인: netstat -p

4)방화벽 설정
=>iptable
- 개요
리눅스 커널 내부의 패킷 필터링 프레임워크인 netfiletr를 제어해서 방화벽, NAT, 패킷 변형 등을 수행하는 명령줄 기반의 보안도구
들어오고 나가는 모든 네트워크 패킷을 검사하고 관리자가 정한 규칙에 따라 패킷을 통과시킬 지, 차단할 지, 혹은 다른 곳으로 전달할지를 결정하는 네트워크 게이트키퍼 역할을 수행

- 장점
커널 레벨의 고성능: 유저 공간이 아닌 리눅스 커널 레이어에서 직접 패킷을 제어하기 때문에 처리 속도가 빠르고 자원을 적게 사용

포트, IP 뿐 아니라 패킷의 상태, 네트워크 인터페이스 카드, MAC 주소, 패킷 문자열 감지 등 매우 정교한 조건 생성이 가능

오랜 시간동안 리눅스 표준 방화벽으로 군용, 기업용 인프라에서 사용되서 레퍼런스와 스크립트 툴이 다양

- 단점
높은 진입 장벽 - 명령어가 복잡하고 가독성이 떨어져서 규칙 하나를 잘못 추가하면 네트워크 전체가 마비되거나 접속이 끊길 수 있음

순서 의존성: 규칙을 위에서부터 아래로 순서대로 검사하기 때문에 규칙 간의 우선순위를 완벽히 이해고 작성해야 함

휘발성 메모리에서 작동: 명시적으로 별도의 파일에 저장하지 않으면 재부팅할 때 설정한 규칙이 모두 날라감

- IP 테이블의 구조: 3대 테이블
Filter(기본 테이블): 패킷을 허용할 지 차단할지 결정하는 방화벽의 핵심 역할

NAT(Network Address Translation): 패킷의 출발지 IP/포트 나 목적지 IP/포트 를 다른 것으로 변환

Mangle: 패킷 헤더의 특정 정보를 마킹하거나 미세하게 수정할 때 사용

- IP 테이블의 구조: 5대 체인
INPUT: 외부에서 서버 자체를 목적지로 들어오는 패킷이 거치는 통로

OUTPUT: 서버에서 외부로 나가는 패킷이 거치는 통로

FORWARD: 서버가 목적지가아니라 서버를 단순히 거쳐서 다른 곳으로 전달되는 패킷이 거치는 통로(라우터/공유기 역할 수행 시 사용)

PREROUTING: 패킷이 네트워크 카드에 도착하자마자 라우팅 경로를 결정하기 전에 거치는 통로

POSTROUTING: 패킷이 라우팅을 마치고 네트워크 카드를 통해 밖으로 나가지 직전에 거치는 통로

- 패킷 처리 규칙
ACCEPT: 패킷을 허용하고 통과

DROP: 패킷을 완전치 차단(보낸 이에게 차단되었다는 응답조차 주지 않고 증발시킴 - 보안상 추천)

REJECT: 패킷을 차단하되 보낸 이에게 거부되었다는 안내 메시지(ICMP 에러)를 되돌려 주는 것

LOG: 패킷의 정보를 시스템 로그(/var/log/syslog)에 기록(패킷 자체는 통과됨)

- 명령어 사용
기본 filter 테이블의 규칙을 번호와 조회: sudo iptables -L -n -v --line-numbers

NAT 테이블 규칙 조회: sudo iptables -t nat -L -n -v --line-numbers

기본 정책 변경
	들어오는 패킷은 기본적으로 모두 차단: sudo iptables -P INPUT DROP

	나가는 패킷은 기본적으로 모두 허용: sudo iptables -P OUTPUT ACCEPT

	거쳐가는 패킷은 기본적으로 모두 차단: sudo iptables -P FORWARD DROP

방화벽 규칙 추가
	옵션
		-A: 체인의 맨 아래에 규칙을 추가
		-I: 체인의 맨 위체 규칙을 삽입
	사용
		로컬 호스트 트래픽 허용: sudo iptables -A INPUT -i lo -j ACCEPT
		이미 연결되었거나 연관된 패킷은 자동으로 허용(원격 접속 끊김 방지): sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
		특정 포트 허용: sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
				    sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
				    sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

		특정 IP 주소 차단: sudo iptables -A INPUT -s 아이피주소 -j DROP

방화벽 규칙 삭제
	특정한 체인의 번호 기반 삭제: sudo iptables -D INPUT 라인번호

	모든 규칙 삭제: sudo iptables -F

포트포워딩(80번 포트로 오면 8080 포트로 포트포워딩)
	sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080

- iptables 규칙을 파일에 저장
패키지를 설치: sudo apt install iptables-persistent

파일에 저장: sudo iptables-save | sudo tee /etc/iptables/rules.v4

파일에서 읽어오기: sudo iptables-restore < /etc/iptables/rules.v4

- 현대 리눅스에서 위치
최신 리눅스에서는 iptables의 복잡함을 해결하기 위해 다양한 대안이 존재

ufw: ubuntu에서 주로 사용되는데 iptable가 너무 복잡해서 초보자도 쉽게 다룰 수 있도록 명령어 체계를 직관적으로 wrapping해 놓은 단순화 도구 - 여전히 백엔드에서 iptables 규칙으로 치환되어 작동

nftables: 차세대 패킷 필터링 프레임워크인데 아직은 호환성 문제때문에 nftables 규칙으로 자동 변환되는 브릿지 툴이 작동하는 경우가 많음


=>ufw
- 개요
Uncomlicated FireWall은 복잡하지 않은 방화벽이라는 의미의 리눅스의 기본 방화벽 관리 도구

iptables를 사용자가 직관적이고 쉽게 다룰 수 있도록 Wrapping하여 명령어를 단순화한 도구

백엔드에서는 여전히 iptables 규칙을 생성하여 커널에 전달하지만 사용자는 sudo ufw allow 80 같이 단 한 줄의 직관적인 명령어로 방화벽을 제어할 수 있게 됨
 
- 핵심 동작 방식
UFW는 기본적으로 Whitelist 방식의 보안 정책을 쉽게 수립할 수 있도록 설계됨

기본 정책: 외부에서 서버로 들어오는 모든 접근은 일단 전부 차단하고 서버 내부에서 외부로 나가는 통신은 전부 허용하는 것이 기본 상태

예외 허용: 기본 정책이 들어오는 모든 접근은 차단이므로 관리자는 웹 서버나 원격 제어처럼 안전하고 필요한 포트만 선택해서 열어주는 방식으로 운영

- 특징 및 장점
명령 체계가 쉬움
	SSH를 허용
		iptables -A INPUT -p tcp --dport 22 -j ACCEPT
		ufw allow ssh

규칙 관리가 쉬움
	확인: ufw status numbered
	삭제: ufw delete 번호 

응용프로그램 프로필 지원
	nginx, apache, openssh 등 유명 패키지를 설치하면 해당 프로그램이 사용되는 포트 정보를 담은 프로필이 UFW에 자동으로 등록되며 관리자는 포트 번호를 일일이 외울 필요없이 ufw allow nginx full 같은 명령으로 관련 포트를 통째로 제어할 수 있음

다중 조건 조합 가능
	단순한 포트 개방을 넘어서서 특정 IP 주소가 TCP 프로토콜로 22번 포트에 접근할 때만 허용한다 와 같은 정교한 방화벽 규칙도 작성할 수 있음

- UFW 상태 확인 및 활성화/비활성화
상태 확인: sudo ufw status verbose

방화벽 활성화: sudo ufw enable

방화벽 비활성화: sudo ufw diable

- 기본 정책 설정
들어오는 모든 접속 차단: sudo ufw default deny incomming

나가는 모든 접속 허용(인터넷을 하고자 하는 경우): sudo ufw default allow outgoing
 
- 방화벽 규칙 추가
포트 번호 기반 설정
	특정 포트 허용: sudo ufw allow 포트번호
	프로토콜 지정 허용: sudo ufw allow 포트번호/tcp 나 udp
	특정 포트 차단: sudo ufw deny 포트번호
	포트 범위 허용: sudo ufw allow 시작번호:끝번호/tcp
서비스 이름 기반 설정
	SSH 허용: sudo ufw allow ssh
특정 IP 기반 설정
	특정 IP 접근만 허용: sudo ufw allow from IP
특정 네트워크 대역 허용: sudo ufw allow from 네트워크주소/서브넷마스크	
특정 IP가 특정 포트에만 접근할 수 있도록 허용: sudo ufw allow from IP주소 to any port 포트번호 proto tcp

- 방화벽 규칙 삭제
	확인: sudo ufw status numbered
	삭제: sudo ufw delete 번호
	명령어를 이용해서 삭제: sudo ufw delete allow 80

- 방화벽 전체 초기화: sudo ufw reset

12. 원격 접속
1)Telnet
=>개요
- Telecommunication Network의 약자로 인터넷이나 로컬 영역 네트워크 연결에 사용되는 네트워크 프로토콜
- 1969년에 처음 개발된 아주 오래된 표준

=>특징
- 원격 접속: CLI를 통해 원격 호스트를 제어
- TCP 기반: 기본적으로 TCP 23번 포트를 사용하여 통신
- 플랫폼 독립적: 운영체제가 달라도 상관없음
- NVT(Network Virtual Terminal): 서로 다른 시스템 환경에서도 명령어를 인식할 수 있도록 가상의 단말기 개념을 사용하여 데이터를 주고 받음

=>장점
- 설치가 간편하고 사용법이 매우 쉬움
- 시스템 리소스 적게 차지
- 오래된 장비와도 호스트 호환성이 뛰어남

=>단점
- 데이터가 암호화되지 않은 평문으로 전송되어 패킷 스니필을 통해 정보가 유출될 위험이 큼

=>현재 엔지니어들이 사용하는 용도
- 포트 개방 확인: telnet IP주소 포트번호

=> 설치 확인: dpkg -l | grep telnet
기본적으로 클라이언트만 설치가 되어 있음

2)SSH
=>개요
- SSH(Secure Shell)는 네트워크 상의 다른 컴퓨터에 로그인하거나 원격 시스템에서 명령을 실행할 수 있게 해주는 보안 네트워크 프로토콜
- 이전에 사용했던 Telnet이나 FTP 등은 데이터를 plaintext 로 전송하여 해킹에 매우 취약했지만 SSH는 모든 통신 내용을 암호화하여 보안성을 획기적으로 높임

=>특징
- 강력한 암호화: 전송되는 모든 데이터를 암호화
- 인증(Authentication): 접속하려고 하는 사용자가 올바른 사용자인지 확인(비밀번호 방식, 공개키 방식 등) 
- 무결성(Integrity): 전송된 데이터가 중간에 위변조되지 않았음을 보장
- 압축: 데이터를 압축해서 전송하기 때문에 네트워크 효율이 좋음
- SSH는 기본적으로 클라이언트-서버 모델로 동작하며 표준 포트는 22번
- 권장되는 인증 방식은 비밀번호가 아닌 SSH Key(공개키/개인키)를 사용하는 방식

=>활용 사례
- 원격 터미널 접속
- SFTP/SCPSSH: 보안 채널을 이용한 안전한 파일 전송
- SSH Tunneling: 보안이 취약한 다른 프로토콜을 SSH 안에 넣어 안전하게 전달
- GIT 원격 저장소: GitHub, GitLab 등에서 코드를 푸시할 때 인증 수단으로 사용 

=>설치 및 동작 접속
- 설치: sudo apt -y install openssh-server
- 서비스 시작: sudo systemctl start ssh
- 부팅 과 함께 서비스 시작: sudo systemctl enable ssh
- 서비스 확인: systemctl status ssh
- 방화벽에서 포트를 해제: sudo ufw allow 22/tcp
- 외부에서 접속: ssh 사용자이름@IP주소 -p 포트번호
- 맨 처음 접속하면 메시지가 출력되는 경우가 있는데 이 메시지는 보안 확인 절차

=>SSH Key를 이용한 접속
- 접속하고자 하는 클라이언트에서 ssh-keygen -t ed25519 라는 명령을 수행(비밀번호 생성 창은 Enter)

- 서버에 키를 등록하기 위해서 ssh-copy-id -p 포트번호 사용자이름@서버주소

- 서버 설정
권한 설정
	chmod 700 ~/.ssh
	chmod 600 ~/.ssh/authorized_keys

SSH 설정 확인 및 수정: sudo nano /etc/ssh/sshd_config
	PubkeyAuthentication yes #주석 해제

	AuthorizedKeysFile      .ssh/authorized_keys #주석 해제

	PasswordAuthentication yes #주석 해제

설정 파일 저장

서버는 ssh를 재시작: sudo systemctl restart ssh

- 클라이언트에서 키를 가지고 접속: sudo ssh -t ~/.ssh/id_ed25519 사용자이름@컴퓨터이름이나 IP주소
sudo ssh -i ~/.ssh/id_ed25519 adam@192.168.0.101

- 접속 간편화: 클라이언트에서 작업 - vi ~/.ssh/config
Host 이름
	HostName 서버IP
	User 사용자계정
	IdentitiFile ~/.ssh/id_ed25519

저장하고 sudo ssh 이름
