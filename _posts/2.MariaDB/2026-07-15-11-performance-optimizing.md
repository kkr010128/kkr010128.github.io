## 1. 인덱스 (INDEX) 개요

- **정의**: 원하는 데이터를 쉽게 찾을 수 있도록 돕는 책의 찾아보기(색인)와 유사한 구조로, 키(Key)와 참조(Reference)를 쌍으로 저장함.
- **목적**: 검색 성능의 최적화임.
- **장점**: 검색 속도가 빨라지고 시스템 전체 성능을 향상시킴.
- **단점**:
    - 추가적인 저장 공간과 생성 시간이 필요함.
    - 데이터 삽입, 수정, 삭제(DML) 작업 시 인덱스 구조(B-Tree)를 함께 수정해야 하므로 성능이 느려짐.

---

## 2. 인덱스 종류 및 구조

### 2.1 클러스터 기반 인덱스 (Clustered Index)

- 모든 데이터가 인덱스 키 컬럼 순으로 물리적으로 정렬되어 저장됨.
- 테이블당 오직 1개만 생성 가능함.
- 기본키(Primary Key) 생성 시 자동으로 설정되며, 없을 경우 Unique + NOT NULL 제약조건 컬럼에 설정됨.

### 2.2 트리 기반 인덱스 (B-Tree Index)

- DBMS에서 가장 일반적인 구조로 루트(Root), 브랜치(Branch), 리프(Leaf) 블록으로 구성됨.
- 리프 블록은 실제 행의 위치를 가리키는 **레코드 식별자**와 양방향 링크(Double Linked List)를 가지고 있어 오름차순/내림차순 검색에 용이함.

## 3. 인덱스 관리 명령어

### 3.1 인덱스 확인

```sql
SHOW INDEX FROM 테이블이름;
```

### 3.2 인덱스 직접 생성

- **문법**: `CREATE [UNIQUE] INDEX 인덱스명 ON 테이블명 (컬럼명);`
- **예제**: EMP 테이블의 ENAME 컬럼에 인덱스 생성

```sql
CREATE INDEX IDX_EMP_ENAME ON EMP(ENAME);
```

### 3.3 인덱스 제거

- **문법**: `DROP INDEX 인덱스명 ON 테이블명;`
- **예제**:

```sql
DROP INDEX IDX_EMP_ENAME ON EMP;
```

## 4. 데이터 스캔 방식

### 4.1 전체 테이블 스캔 (Full Table Scan)

- **HWM(High Water Mark)** 아래의 모든 블록을 읽어 조건에 맞는 데이터를 추출함.
- **발생 경우**: WHERE 절 조건이 없거나, 인덱스가 존재하지 않을 때, 또는 검색 결과가 전체 데이터의 10~15% 이상일 때 옵티마이저가 선택함.

### 4.2 인덱스 스캔 (Index Scan)

- **인덱스 유일 스캔 (Unique Scan)**: 유일 인덱스를 사용해 '=' 조건으로 조회할 때 발생함 (결과가 1건임).
- **인덱스 범위 스캔 (Range Scan)**: 한 건 이상의 데이터를 추출할 때 사용하며, `LIKE`, `BETWEEN` 등 범위 조회 시 발생함.
- **인덱스 역순 범위 스캔**: 리프 블록의 링크를 이용해 내림차순으로 읽으며, 최댓값을 찾을 때 효율적임.

## 5. 옵티마이저 조인 (Join) 최적화

|조인 방식|설명|특징 및 힌트|
|:--|:--|:--|
|**NL Join**|중첩 반복문 방식으로 조인함.|랜덤 액세스 방식. 결과 행 수가 적은 테이블을 선행으로 두는 것이 유리함. `sql /*+ use_nl(선행테이블) */`|
|**Sort Merge Join**|조인 컬럼 기준으로 정렬 후 조인함.|인덱스가 없거나 범위가 넓은 데이터 처리에 유리함. 비동등 조인도 가능함. `sql /*+ ordered use_merge(선행) */`|
|**Hash Join**|해시 함수를 이용해 해시 테이블을 생성함.|정렬이나 랜덤 액세스 부담이 없음. 동등 조건('=')에서만 사용 가능함. `sql /*+ use_hash(선행) */`|

## 6. 고급 기능 (실무 보강)

### 6.1 테이블 파티션 (Table Partition)

- 대용량 테이블을 물리적으로 여러 파일에 분리하여 저장함.
- **종류**: Range(범위), List(목록), Hash(해시), Composite(합성) 분할.
- **장점**: 특정 파티션만 탐색하여 성능이 향상되고 백업/복구가 용이함.

### 6.2 전체 텍스트 검색 (Full-Text Search)

- 긴 문장 내부의 단어나 문장을 검색하기 위한 부가 기능임.
- InnoDB와 MyISAM 테이블에서 `CHAR`, `VARCHAR`, `TEXT` 타입에만 생성 가능함.
- **연산자 활용**:
    - `+단어`: 필수 포함.
    - `-단어`: 제외.
    - `"단어"`: 정확히 일치.

---

> [!tip] **인덱스 설계 팁**
> 
> - WHERE 문에 자주 사용되고 데이터 중복도가 낮은(선택도가 좋은) 컬럼에 인덱스를 우선 생성함.
> - 조인 성능 향상을 위해 외래키(FK) 컬럼에도 인덱스 생성을 권장함.
