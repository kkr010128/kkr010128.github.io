## 1. 트랜잭션(Transaction) 개요

- **정의**: 데이터베이스에서 발생하는 여러 개의 SQL 명령문을 하나의 논리적 작업 단위로 묶어서 처리하는 것임.
- **원칙**: 'All-or-Nothing' 방식으로 처리됨. 묶인 명령어가 모두 성공하면 반영하고, 하나라도 실패하면 전체를 취소함.
- **목적**: 데이터의 일관성을 유지하고 안정적인 복구를 보장하기 위함임.

### 1.1 트랜잭션의 성질 (ACID)

1. **원자성(Atomicity)**: 트랜잭션 내 작업이 부분적으로 실행되다가 중단되지 않음을 보장함.
2. **일관성(Consistency)**: 성공 완료 후 데이터베이스는 언제나 일관된 상태를 유지함.
3. **독립성(Isolation)**: 수행 중인 트랜잭션에 다른 트랜잭션의 연산이 끼어들지 못하게 함.
4. **지속성(Durability)**: 성공 완료된 트랜잭션 결과는 시스템 장애가 발생해도 영구적으로 반영됨.

---

## 2. 임시 작업 영역 (Undo Segment)
트랜잭션을 사용하기 위해 관계형 데이터베이스들은 임시 작업 영역을 이용
- 원본 데이터를 복제해서 생성
- 원본 데이터를 수정하면서 작업 내역 저장

- **동작 방식**: 데이터를 변경하기 전후 상태의 복사본을 임시 영역(오라클: Undo Segment, SQL Server: Transaction Log)에 기록함.
- **반영 과정**: 모든 명령 성공 시 `COMMIT`을 통해 변경 후 데이터를 실제 DB에 영구 저장함. 실패 시 `ROLLBACK`으로 변경 전 데이터를 다시 써넣어 작업을 취소함.

---

## 3. TCL 명령어 (Transaction Control Language)

### 3.1 COMMIT (반영)

- **설명**: 트랜잭션 내의 모든 작업 내용을 데이터베이스에 영구 저장하고 트랜잭션을 종료함.
- **문법**: `sql COMMIT;`
- **결과**: 이전 데이터가 완전히 업데이트되며, 모든 사용자가 변경된 결과를 확인할 수 있음.

### 3.2 ROLLBACK (취소)

- **설명**: 트랜잭션 시작 이후 또는 마지막 `COMMIT` 이후의 모든 변경 사항을 취소하고 트랜잭션을 종료함.
- **문법**: `sql ROLLBACK;`
- **결과**: 데이터가 트랜잭션 시작 이전의 상태로 되돌아감.

### 3.3 SAVEPOINT (저장점)

- **설명**: 현재 트랜잭션을 작게 분할하여 특정 지점까지만 취소할 수 있도록 표시를 남기는 기능임.
- **문법**:
    - 지정: `sql SAVEPOINT 별칭;`
    - 취소: `sql ROLLBACK TO 별칭;`
- **예제**:

```sql
DELETE FROM tCity WHERE name = '서울';
SAVEPOINT s1; -- 저장점 s1 설정
DELETE FROM tCity WHERE name = '부산';
ROLLBACK TO s1; -- '부산' 삭제만 취소됨, '서울'은 삭제된 상태 유지
```

## 4. 트랜잭션 모드 (Transaction Mode)

|모드|설명|특징|
|:--|:--|:--|
|**자동 커밋 (Auto)**|명령 실행 즉시 DB에 반영됨.|MariaDB, MySQL의 기본값임. 속도는 빠르나 취소가 불가능함.|
|**수동 커밋 (Manual)**|명시적으로 `COMMIT`을 내려야 반영됨.|오라클의 기본값임. 안전하지만 데이터 일관성 유지를 위해 락(Lock)을 활용함.|

## 5. Lock 및 격리 수준 (Isolation)

### 5.1 Lock (잠금)

- **목적**: 한 사용자가 데이터를 변경하는 동안 다른 사용자가 동일 데이터를 수정하지 못하도록 대기시켜 일관성을 유지함.
- **종류**:
    - **공유락(Shared Lock)**: 읽기는 허용하나 쓰기는 금지함.
    - **배타락(Exclusive Lock)**: 읽기와 쓰기 모두 금지함.

### 5.2 동시성 부작용 (Side Effects)

격리 수준이 낮을 때 발생할 수 있는 문제들임.

- **손실 업데이트**: 두 트랜잭션이 동시에 값을 수정하여 한쪽의 갱신 내용이 사라짐.
- **Dirty Read**: 커밋되지 않은 트랜잭션의 데이터를 다른 곳에서 읽어 발생하는 오류임.
- **Phantom Read**: 트랜잭션 도중 새로운 레코드가 삽입되어 없던 데이터가 나타나는 현상임.

### 5.3 격리 수준 (Isolation Level)
- 트랜잭션 작업 도중 어느 정도까지 작업을 허용할 것인가 하는 것
- 트랜잭션 작업 도중인 데이터는 외부에서는 기본적으로 읽기와 쓰기가 되지 않음: SSERIALIZABLE

- **READ UNCOMMITTED**: 커밋되지 않은 데이터도 읽음. 가장 낮음.
- **READ COMMITTED**: 커밋된 데이터만 읽음. 일반적인 기본 설정임.
- **REPEATABLE READ**: 트랜잭션 중 읽은 데이터를 다른 사용자가 수정하지 못하게 함.
- **SERIALIZABLE**: 가장 높은 수준으로, 데이터 삽입조차 허용하지 않아 성능은 낮으나 정확함.

---

> [!warning] **주의사항**
> 
> - DDL(`CREATE`, `ALTER`, `DROP` 등)과 `TRUNCATE`는 실행 시 **자동 커밋**이 발생하므로 이전 DML 작업이 롤백되지 않음을 유의해야 함.
> - 수동 모드에서는 락으로 인한 대기 상태가 길어질 수 있으므로 작업이 끝나면 반드시 `COMMIT`이나 `ROLLBACK`을 수행해야 함.
