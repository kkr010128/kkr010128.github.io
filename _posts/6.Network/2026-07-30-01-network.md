## 2 ) OSI 7 계층
---
- 과거에는 통신용 규약이 표준화되지 않고 각 벤더에서 별도로 개발함
- 이로 인해 호환되지 않는 시스템이나 애플리케이션이 많고 통신이 불가능했음
- 이를 하의 규약으로 통합하려는 노력이 현재의 OSI7계층

→ (강사님): 예전에는 Win과 Mac이 사용하는 인터넷 케이블이 달라서 불편함이 많았다

- OSI 계층이 네트워크 동작을 나누어 이해하고 개발하는 데 많은 도움이 됨
- 네트워크의 주요 레퍼런스 모델로 활용되고 있으나 최근에는 TCP/IP 프로토콜 스택 기반으로 되어있음

| Layer        | 설명    | Handling |
| ------------ | ----- | -------- |
| Application  | 응용    | Data     |
| Presentation | 표현    | Data     |
| Session      | 세션    | Data     |
| Transport    | 전송    | Segments |
| Network      | 네트워크  | Packets  |
| DataLink     | 데이터링크 | Frames   |
| Physical     | 물리    | Bits     |

=> 복잡한 데이터 전송 과정을 계층 관점에서 보면 이해가 쉽다

- OSI 7계층은 다시 2개의 블럭으로 나눌 수 있음
	- 1 ~ 4 계층: `Data Flow Layer (하위 계층 - 기계)`
	- 5 ~ 7 계층: `Application Layer (상위 계층 - 인간)`

- Data Flow Layer
	- 데이터를 상대방에게 잘 전달하는 역할 수행
	- 애플리케이션 개발자는 Application Layer 프로토콜을 개발 또는 이용할 때 Data Flow Layer는 고려하지 않음. 데이터를 표현하는데 초첨을 둠
- Application Layer
	- 애플리케이션 개발자들이 고려해야 할 영역
	- 네트워크 엔지니어는 애플리케이션 계층은 심각하게 고려하지 않음
	- 애플리케이션 개발자는 하향식으로, 네트워크 엔지니어는 상향식으로 네트워크 인식

### 1계층 (Pysical Layer)
- 물리적 연결과 관련된 정보를 정의
- 전기 신호를 전달하는 데 초점이 맞추어져 있음
- 장비로는 Hub, Repeater, Cable, Connectorm Tranceiver, TAP 등이 존재
- 1계층 장비는 들어온 전기 신호를 그대로 잘 전달하는 것이 목적
- 주소의 개념이 없으며 전기 신호가 들어온 포트를 제외하고 모든 포트에 동일한 신호를 전송

 > *TAP : 네트워크 모니터링 및 패킷 분석을 위해 전기 신호를 다른 장비로 복제해주는 장비
> 	→ Wireshark, IDS, IPS, 패킷 분석기 등에 전달 - 원래 통신에 영향 없음 	

### 2계층 (Data Link Layer)
- 전기 신호를 모아 알아볼 수 있는 데이터 형태로 변환
- 주소 정보를 정의하고 정확한 주소로 통신이 되도록 하는 데 초점을 둠
- 1계층에서는 출발지와 목적지 주소를 구분할 수 없으나 2계층에서는 확인함
- 주소를 확인하고 올바르게 보내진 것이 맞는지, 처리 대상인지 검사 후 데이터 처리 수행
- 전기 신호를 모아 데이터 형태로 처리
	→ 데이터에 대한 에러를 탐지하거나 고치는 역할 수행
- 주소 체계가 생겼다? → 동시에 여러 장비와 통신 가능
- 무작정 데이터를 전송하지 않고 수신 가능 여부를 확인해야함 → Flow Control
- 2계층에서 동작하는 네트워크 구성 요소는 NIC(Network Interface Card - 랜카드)와 Switch

가장 중요한 특징 → MAC 이라는 주소 체계가 있다는 것
- 2계층에서 동작하는 NIC와 Switch는 모두 MAC 주소를 인식 가능
	- Switch는 MAC 주소를 확인 해 통신해야 할 포트를 지정하여 내보내는 것이 가능

- **NIC 동작**
	- 전기 신호를 데이터 형태로 생성
	- 목적지와 출발지 MAC 주소 확인
	- 네트워크 인터페이스 카드의 MAC 주소 확인
	- 목적지 MAC 주소와 NIC의 MAC 주소가 일치하면 데이터 처리, 다르면 폐기

- **Switch 동작**
	- 노드가 어떤 MAC 주소이고 어느 포트가 연결 됐는지 주소 학습 가능
	- 학습한 주소를 기반으로 노드들이 통신할 때 적절히 필터링, 정확한 포트로 포워딩
	- 허브는 한 포트에서 신호가 오면 전체 포트로 신호 전달
		→ 전체 네트워크에서 오직 하나의 장비만 데이터를 보낼 수 있음
	- 스위치는 적절한 필터링과 포워딩 기능으로 통신이 필요한 포트만 사용
		- 네트워크 전체에 불필요한 처리 감소, 효율성 향상, 이더넷 기반 네트워크 급증 계기로 작용

 > Forwarding : 출발지 주소를 변경하지 않고 전송(그대로 토스하는 느낌)
> 	→ Redirect와 반대

### 3계층 (Network Layer)
- IP 주소와 같은 논리적인 주소 정의
- 데이터 통신 시 두 가지 주소가 사용됨
	- MAC (2계층)
	- IP (3계층)
- IP가 왜 논리적인지?
	→ 사용자가 환경에 따라 변경 가능
	→ 네트워크 주소와 호스트 주소로 나뉨
- 3계층을 이해할 수 있는 장비나 노드는 주소 정보로 자신의 네트워크 및 원격지 구분 가능
	- 어디로 가야하죠 →  가야할 원격지 경로 지정 가능
	- Router는 3계층에서 동작
	- Router는 IP를 이용해 최적의 경로를 찾고 해당 경로로 패킷 전송 수행


### 4계층 (Transport Layer)
- 데이터들이 정상적으로 잘 보내지도록 확인하는 역할
- 패킷 네트워크는 데이터를 분할해 패킷 단위로 전송
	- 중간에 패킷 유실 또는 순서가 바뀌는 경우 있음
		→ 이를 해결하기 위해 4계층 존재
- 패킷에 보내는 순서를 명시한 것 → Sequence Number
- 받는 순서를 명시한 것 → ACK(Acknowledgement Number)
- 장치 내의 애플리케이션 구분 가능하도록 포트 사용
- 4계층에서 동작하는 장비는 port와 sequence, ACK를 사용함
	→ 부하 분산, 보안 정책 수립해 패킷을 통과 및 차단하는 기능 수행
		→ 방화벽, 로드 밸런서

### 5계층 (Session Layer)
- 양 끝 단의 응용 프로세스가 연결을 성립하도록 도와줌
- 연결이 안정적으로 유지 되도록 관리함
- 작업이 끝나면 연결을 끊음
- TCP/IP 세션을 생성하고 삭제하는 것, 에러로 인한 중단된 통신에 대해 복구 및 재전송 수행

### 6계층 (Presentation Layer)
- 표현 방식이 다른 애플리케이션 또는 시스템 간 통신을 돕기 위해 통일된 구문 형식으로 데이터를 변환
- 번역기나 변환기의 역할을 수행하는 계층
	- 사용자 시스템의 응용 계층에서 데이터 형식 상의 차이를 다루는 부담 줄여줌
- MIME 인코딩, 암호화, 압축, 코드 변환 등의 동작 수행

### 7계층 (Application Layer)
- 네트워크 소프트웨어의 UI • 사용자 입출력 부분 정의

### 계층 별 프로토콜과 장비


| Layer | Protocol               | Device         |
| ----- | ---------------------- | -------------- |
| 7     | HTTP, HTTPS, TELNET    | ADC, NGFW, WAF |
| 6     | TLS, SSH               | ( )            |
| 5     | NFS, RPC, SSH          | ( )            |
| 4     | TCP, UDP               | 로드밸런서, 방화벽     |
| 3     | ARP, IPv4, IPv6, NAT 등 | 라우터, L3 스위치    |
| 2     | IEEE 802.2, FDDI       | 스위치, 브릿지, NIC  |
| 1     | RS-232, RS0449         | 케이블, 허브, TAP   |

 > **ADC** : Application Delivery Controller
> 	→ 고성능 로드 밸런서 + 애플리케이션 최적화 장비
>
 > **NGFW** : Next Generation FireWall
> 	→ 애플리케이션 분석, IPS, IDS 등의 기능 수행
>
 > **WAF** : Web Application Firewall
> 	→ HTTP나 HTTPS 분석하여 웹 공격 차단

## 3 ) TCP/IP Protocol Stack
---
- 현대의 네트워크는 TCP/IP 프로토콜과 이더넷으로 이루어져 있음
- 일부 특수한 환경에서는 다른 프로토콜이 사용되기도 함
	- 어떤 것을 선택할 지 고민하진 않음

 -  (강사님) : Nvidia GPU끼리 통신하던 프로토콜이 기업의 장기적 이익을 위해 공개됨
	 → NVLink, NVSwitch, CUDA
	 
- 역사적 배경, 만든 조직 또는 프로토콜이 제작된 목표에 따라, 기술 및 표준을 만들 때 성향이 많이 반영 됨
	- TCP/IP는 이론보다 실용성에 중점을 둔 프로토콜 스택

###  TCP/IP는 4 계층으로 구분

	- Application Layer
	- Presentation Layer
	- Session Layer
- Transport 
	- Transport
- Internet 
	- Network Layer
- Network Access
	- Data Link Layer
	- Physical Layer


## 4 ) Encapsulation & Decapsulation
---
- 데이터를 보내는 것 → Encapsulation
- 데이터를 받는 것 → Decapsulation

### 패킷 기반 네트워크
- 현대의 네트워크는 대부분 패킷 기반 네트워크
- 패킷 네트워크는 작은 데이터 단위인 패킷으로 쪼개 보냄
	- 하나의 통신이 회선 전체를 점유하지 않도록
	- 여러 노드가 동시에 통신을 할 수 있도록 하기 위함
### 데이터 전송
- 보내는 쪽에서 상위 계층 프로토콜을 이용해 데이터 생성
- Transport 계층에서 4계층 헤더를 추가(port)하여 3계층으로 전달
- Network 계층에서 받은 데이터(Segment)에 3계층 헤더(IP) 추가하여 2계층으로 전달
- DataLink 계층에서는 받은 데이터(Packet)에 2계층 헤더(MAC) 추가
- Physical 계층에서는 전기 신호로 변경하여 목적지로 전송
→ Encapsulation 

- 받는 쪽에서  물리계층에서 데이터를 변환해 데이터 링크 계층으로 전송
- DataLink 계층에서 2계층 헤더를 제거 후 네트워크 계층으로 전송
- Network 계층에서 3계층 헤더를 제거후 전송 계층으로 전송
- Transport 계층에서 4계층 헤더를 제거아호 애플리케이션 계층으로 전송해 데이터 해석
### MSS & MTU
- 애플리케이션에서 데이터를 만들어 보낼 때네트워크 상황에 맞게 하위 계층에서 데이터를 쪼개어 전달
- 네트워크에서 수용할 수 있는 크기를 역산정해 데이터가 적절한 크기로 쪼개질 수 있도록 유도함
	- MSS(Maximum Segment Size)
- 네트워크에서 한 번에 보낼 수 있는 데이터 크기 MTU (Maximum Transmission Unit)이라 함
	- 일반적 이더넷에서는 1,500 바이트
- 3계층과 4계층 헤더의 크기가 각각 20바이트이므로 1460 바이트가 MSS
