### Q. int는 4바이트이고 char는 1바이트인데, 숫자는 char로 저장하는 것이 더 효율적인 것 아닐까?

강의 중 자료형의 크기를 설명하면서 `char`는 1바이트, `int`는 4바이트라고 배웠다.

그렇다면 숫자를 저장할 때도 `char`를 사용하면 메모리를 4배 절약할 수 있으므로 더 효율적인 것은 아닐까?

### A. 저장할 수 있는 값의 범위와 CPU의 처리 방식을 함께 고려해야 한다.

자료형은 단순히 메모리 크기만으로 선택하는 것이 아니다.

가장 먼저 고려해야 하는 것은 **얼마나 큰 값을 저장해야 하는지**이다.

대표적인 자료형의 크기와 표현 가능한 범위는 다음과 같다.

| 자료형 | 크기 | 표현 범위(일반적인 Signed 기준) |
| ------ | ---- | ------------------------------ |
| `char` | 1 Byte | -128 ~ 127 |
| `short` | 2 Byte | -32,768 ~ 32,767 |
| `int` | 4 Byte | 약 -21억 ~ 21억 |

예를 들어 나이를 저장한다면 `char`만으로도 충분하다.

하지만 학생 수, 파일 크기, 금액, 배열의 인덱스처럼 범위가 커질 수 있는 데이터는 `int`가 필요하다.

즉, **메모리를 아끼기 위해 작은 자료형을 사용하는 것이 아니라, 저장해야 하는 값의 범위에 맞는 자료형을 선택하는 것이 원칙**이다.

### 메모리만 작은 것이 항상 성능이 좋은 것은 아니다.

현대 CPU는 보통 32비트 또는 64비트 단위로 데이터를 처리한다.

따라서 `char`를 계산하더라도 내부적으로는 `int` 크기로 변환하여 연산하는 경우가 많다.

예를 들어 다음 코드에서

```c
char a = 10;
char b = 20;

char c = a + b;
```

실제로는 `a`와 `b`가 연산 과정에서 `int`로 승격(Integer Promotion)된 뒤 계산된다.

즉,

```c
int temp = (int)a + (int)b;
c = (char)temp;
```

와 유사한 과정이 내부적으로 수행된다.

따라서 단순히 `char`를 사용한다고 해서 연산이 더 빠르거나 CPU 사용량이 줄어드는 것은 아니다.

### 그렇다면 언제 char를 사용할까?

`char`는 숫자를 저장하기 위해 만들어진 자료형이라기보다 **1바이트 크기의 데이터를 표현하기 위한 자료형**이다.

대표적인 사용 예시는 다음과 같다.

- 문자 저장 (`'A'`, `'B'`)
- ASCII 문자 표현
- 작은 범위의 정수
- 바이트 단위 데이터 처리
- 파일 및 네트워크 패킷 처리

특히 네트워크 프로그래밍이나 운영체제에서는 데이터를 바이트 단위로 다루기 때문에 `char` 또는 `unsigned char`를 자주 사용한다.

### 메모리가 중요한 경우도 있다.

임베디드 시스템처럼 메모리가 매우 제한적인 환경에서는 자료형 선택이 중요하다.

예를 들어 센서 값이 항상 `0~100`이라면 `int` 대신 `uint8_t`를 사용하여 메모리를 절약할 수 있다.

반대로 일반적인 애플리케이션에서는 유지보수성과 연산 효율을 고려해 `int`를 사용하는 경우가 많다.

즉, 메모리 절약보다 코드의 안정성과 범용성을 우선하는 경우가 대부분이다.

### 자주 하는 오해

- **char가 1바이트이므로 항상 int보다 효율적이다.**
  - 아니다. 저장 가능한 값의 범위가 매우 작으며 연산 시에는 대부분 `int`로 변환된다.

- **숫자는 모두 char로 저장하면 메모리를 절약할 수 있다.**
  - 저장 가능한 범위를 초과하면 오버플로우가 발생하므로 적절한 자료형을 선택해야 한다.

- **char는 문자만 저장하는 자료형이다.**
  - 아니다. 1바이트 정수형이며 문자 역시 숫자로 저장된다.

### 정리

- `char`는 1바이트, `int`는 일반적으로 4바이트이다.
- 자료형은 메모리 크기보다 저장해야 하는 값의 범위를 기준으로 선택한다.
- `char`는 연산 과정에서 대부분 `int`로 자동 승격된다.
- 따라서 `char`가 항상 더 빠르거나 효율적인 것은 아니다.
- 일반적인 프로그램에서는 `int`를, 메모리가 중요한 환경에서는 필요한 범위에 맞는 작은 자료형을 사용하는 것이 바람직하다.
