## 1 ) 개요
---
- clien와 server 사이에서 데이터를 중개하는 대리인 역할 수행하는 서버
- 사용자가 다른 곳과 통신을 하고자 할 때 직접 접속하는 대신 프록시 서ㅓㅂ가 사용자의 요청을 받아 전달, 다시 사용자에게 보내주는 방식

### 기본 동작 원리
- 요청: 클라이언트가 다른 곳과 통신ㅇ르 하고자 할 때 요청을 프록시 섭버로 전송
- 중개: 프록시 서버는 클라이언트 대신 목적지 서버에 데이터를 요청
- 응답: 목적지 서버에서 보낸 응답을 프록시 서버가 받은 후 이를 다시 클라이언트에게 전공

## 2 ) 사용 목적 및 특징
---
### 익명성 및 보안(Privacy & Security)
- IP 주소 숨김
	- 목적지 서버는 클라이언트의 실제 IP가 아닌 프록시 서버의 IP만 알 수 있음
- 방화벽 역할
	- 외부의 직접적인 공격으로부터 내부 내트워크를 보호, 위험한 사이트로의 접근을 사전에 차단 가능
### 성능 향상
- Caching
	- 자주 방문하는 곳의 데이터를 프록시 서버에 임시로 저장
	- 동일한 요청이 들어오면 서버까지 가지 않고 저장된 데이터를 즉시 반환
	- 속도를 높이고 대역폭을 전환
### 접근 제어 및 필터링
- 유해 사이트 차단
- 특정 지역에서만 접근 가능한 콘텐츠를 우외하여 접속할 때 사용(VPN 이용 가능)
### 종류
- Forward Proxy
	- client 앞단에서 서버로 가는 요청을 가로챔
	- 목적은 보안, 익명성, 내부망에서 외부 접속 관리 등
- Reverse Proxy
	- server 앞단에서 클라이언트의 요청을 서버로 분산
	- 목적은 로드 밸런싱, 서버 보안, SSL 암호화 처리 등
## 3 ) 설치 및 구현
---
### SERVER
- 패키지 설치 
	- → `sudo apt install squid -y`
- 설정 파일 수정 
	- → `sudo nano /etc/squid/squid.conf`
```bash
acl myserver src 10.0.2.0/24
http_access allow myserver
cache_dir ufs /var/spool/squid 1000 16 256
visible_hostname myserver
```
- 방화벽 중지(안 해도 됨)
	- sudo ufw disable
- squid 재시작
	- sudo systemctl restart squid
### CLIENT
- 설정 파일을 열어 작성
	- sudo nano /etc/environment
- 변경 내용 적용
	- source /etc/environment
- apt에 적용할 설정 파일 생성 및 작성
	- sudo nano /etc/apt/apt.conf.d/99proxy
```c
	Acquire::http::Proxy "http://10.0.2.3:3128/";
	Acquire::https::Proxy "http://10.0.2.3:3128/";
```
### 확인(Header)
- `curl -I https://www.google.com`

```
HTTP_PROXY="http://10.0.2.3:3128/"
HTTPS_PROXY="http://10.0.2.3:3128/"
FTP_PROXY="http://10.0.2.3:3128/"

```

```sh
# 변경 내용 적용
source /etc/environment
```

```sh
sudo nano /etc/apt/apt.conf.d/99proxy
```

```
Acquire::http::Proxy "http://10.0.2.3:3128/";

```
